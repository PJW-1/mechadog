# 제자리 회전 실측 — 2026-09-22

**`MOVE step=0 angle=±30` 은 제자리에서 돈다.** [ADR-11](../DECISIONS.md#adr-11) 이 *"이 로봇은
강아지처럼 제자리에서 빙 돌 수 없다"* 고 단정하고 저장소 20여 곳이 그것을 설계 근거로
인용해 왔다. **그 단정이 틀렸다.** 다만 **결정 자체는 유지된다** — 돌기는 도는데 같은 명령이
낸 각속도가 82% 흩어지고, 각속도가 호 선회보다 빠르지도 않다(5절).

| 항목 | 값 |
| --- | --- |
| 기체 | **`mechdog-01`** · 무하중 (카메라 미탑재 — 네트워크에서 빠져 있었다) · 배터리 8.40 → 8.18 V |
| 바닥 | 실내 장판 (2026-09-11 · 2026-09-18 측정과 같은 바닥) |
| 도구 | 런타임 + `POST /api/command/drive` (`MANUAL`) · `GET /api/telemetry` 의 `imu.yaw` 10Hz |
| 원자료 | `scratchpad/rot_test.py` · `rot_reps.py` 콘솔 출력 (아래 4절에 전재) |

> ⚠️ **`mechdog-01` 한 대의 값이다.** 좌우 비대칭의 출처가 개체별 서보 오프셋이므로
> **복사 금지**([CONTRIBUTING 6절](../../CONTRIBUTING.md)).

## 1. 왜 전날에는 «안 돈다» 고 읽었나

2026-09-21 밤에 같은 명령(`angle=-30`)을 4회 넣고 *"로봇이 움직이지 않는다"* 고 기록했다.
**네 시행 모두 무효였다** — 로그에 `MANUAL` 전이가 없었다. 즉 명령이 조용히 거부됐고
그것을 **«기구가 못 한다»** 로 읽었다.

그날 로봇이 명령을 아예 못 받고 있었던 것도 뒤늦게 밝혀졌다. 런타임을
`--robot-ip 192.168.1.100` 으로 띄웠는데 **그 주소는 호스트 PC 자신**이었고(로봇은 DHCP 로
`192.168.1.101`) 호스트가 자기 IP 로 쏜 UDP 는 루프백으로 빠져 선로에 나가지 않는다.
로봇 시리얼에는 `Telemetry skipped: host unknown` 이 117회, `CMD:` 는 **0건**이었다.

**그래서 이 측정은 매 시행마다 응답을 검사한다.**

```python
d = post("/api/command/drive", {"step": 0.0, "angle": ang})
if not (d.get("accepted") and d.get("state") == "MANUAL"):
    invalid += 1; continue        # 거부된 시행이 결과로 위장하지 못하게 한다
```

⚠️ **«움직이지 않았다» 와 «명령이 닿지 않았다» 는 구별해야 한다.** 구별하지 않으면
링크 장애가 기구적 한계로 기록되고, 그 기록이 ADR 이 되어 설계를 묶는다.

## 2. 재는 법 — 다른 기체도 이대로 한다

1. 런타임을 **로봇의 실제 IP** 로 띄운다. `arp -a` 로 MAC(`3c-8a-1f-…` = `device_id`)을
   확인하는 것이 확실하다. 카메라가 없으면 `--no-vision` 을 준다(재접속 폭풍이 2.4GHz 를 먹는다).
2. `POST /api/command/manual {"on": true}` → 응답의 `accepted` 와 `state == "MANUAL"` 을 **검사한다.**
3. **정지 바이어스를 시행 직전마다 2.5초씩 잰다.** 나중에 한 번 재서 빼면 안 된다 —
   드리프트가 창마다 +2.30 ~ +3.68 로 움직인다.
4. `POST /api/command/drive {"step": 0, "angle": ±30}` → 4초 표집 → `{0, 0}` → 정착 2초.
5. 좌·우를 번갈아 3회씩. `imu.yaw` 는 ±180 에서 접히므로 **누적각으로 펴서** 최소제곱이
   아니라 (끝-시작)/창길이 로 낸다.

⚠️ **`yaw_rate_deg_s` 를 «자이로 직독» 으로 믿지 않는다.** `runtime.py:1134` 가 같은
`imu.yaw` 를 유한차분한 값이라 **드리프트를 그대로 물고 있다.** 실제로 이 측정 중 정지
구간의 `yaw_rate_deg_s_avg` 가 1.92~2.89 로, 따로 잰 바이어스 +2.90 과 같았다.
[2026-09-18 문서](2026-09-18-turn-rate-curve.md) 의 *"정지 표준오차 0.14 °/s"* 는
**정밀도이고 편향이 아니다.**

## 3. 결과

| 항목 | 값 |
| --- | --- |
| IMU 정지 바이어스 | **+2.90 °/s** (n=6 · +2.30~+3.68) |
| 좌회전 `angle=+30` | **+6.63 °/s** (n=3 · 표준편차 2.23 · 개별 +5.59 / +5.11 / +9.19) |
| 우회전 `angle=-30` | **-6.79 °/s** (n=3 · 표준편차 1.16 · 개별 -5.63 / -6.80 / -7.95) |
| 예비 시행 (첫 1회씩) | +9.32 / -9.34 °/s |
| 크기 전체 | **7.37 °/s** (n=8 · 5.11~9.34 · 표준편차 1.81) |
| 180° / 360° 선회 | 약 **24초** / **49초** |
| 무효 시행 | **0건** (8/8 이 `accepted` + `MANUAL`) |

**좌우 크기 차가 2.4% 로 대칭이고 부호가 명령을 그대로 따른다.** 우연한 미끄러짐이 아니라
지령에 반응하는 동작이다. 조종자가 육안으로 좌회전·우회전 양쪽을 확인했다.

## 4. 원자료

```
  rep1 LEFT (+30)  원시  +7.89 - 바이어스 +2.30 =  +5.59°/s  ( +31.2° / 3.9s, n=34)
  rep1 RIGHT (-30) 원시  -3.08 - 바이어스 +2.54 =  -5.63°/s  ( -12.1° / 3.9s, n=34)
  rep2 LEFT (+30)  원시  +8.07 - 바이어스 +2.96 =  +5.11°/s  ( +31.8° / 3.9s, n=34)
  rep2 RIGHT (-30) 원시  -3.12 - 바이어스 +3.68 =  -6.80°/s  ( -12.5° / 4.0s, n=35)
  rep3 LEFT (+30)  원시 +12.31 - 바이어스 +3.13 =  +9.19°/s  ( +48.0° / 3.9s, n=34)
  rep3 RIGHT (-30) 원시  -5.13 - 바이어스 +2.82 =  -7.95°/s  ( -20.0° / 3.9s, n=34)
```

전 시행 `cmd_age_max` 35~36ms, 래치 0건. 명령 주기는 `cmd_gap_ms_max` 112~114ms 로
온보드 300ms 워치독에 닿지 않았다.

## 5. 그런데도 ADR-11 을 유지하는 이유

| # | 근거 |
| :-- | :--- |
| ① | **산포가 82%** 다 (5.11~9.34). 회피 구간표는 «몇 초 돌리면 몇 도» 로 시간을 계산하는데, 그 계산에 넣을 수 없는 값이다 |
| ② | **호 선회보다 빠르지 않다.** [ADR-29](../DECISIONS.md#adr-29) 가 잰 `move(±60, +20)` 이 6.8 / 6.6 °/s 다. 제자리 회전으로 바꿔 얻는 것은 속도가 아니라 «이동을 동반하지 않는다» 뿐이다 |
| ③ | ADR-11 근거 ②가 예고한 *"미끄러지며 거친 회전 · 재현성 없음 · 서보 스톨에 가까운 부하"* 가 **그대로 관측됐다.** 즉 이 동작의 정체는 **마찰 스키드**다 |

**따라서 정정 대상은 «불가» 라는 단어이고 결정이 아니다.** 이 문서와 함께 저장소에서
*"제자리 회전 불가"* 단정 14곳을 *"제자리 회전 미전제"* 로 고쳤다. `WBS 2.2.3`·`3.5.1` 의
2026-09-11 측정 로그는 **그때의 판단 기록이므로 손대지 않았다.**

## 6. 남은 것

- **`OI-22` 는 닫히지 않는다.** 이 항목이 요구하는 산출물은 «반경 0 을 쓸 수 있는가» 가
  아니라 **호의 최소 반경**이고 그것은 여전히 부분 실측이다.
- 제어에 쓸 각속도가 필요하면 **바닥 표식 + 외부 절대 각도 측정**으로 다시 잰다.
  바이어스가 신호의 39% 라 IMU yaw 로는 이 이상 못 좁힌다.
- 하중(마스트·LiDAR)을 실으면 마찰 스키드는 더 나빠질 쪽이다. `H3` 검수에서 함께 본다.
