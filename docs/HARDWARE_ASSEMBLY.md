## 0. 왜 무납땜을 목표로 하는가

팀에 인두 사용 경험이 보장되지 않고, **발주 기회가 1회**이므로 부품을 태우면 복구할 수 없다.
그리고 **실수 비용이 부위별로 크게 다르다.**

| 대상 | 죽으면 |
| :--- | :--- |
| XIAO · ESP32 DevKit | 1~2만원. 예비 보유 |
| **LiDAR** | **재발주 불가 → Phase 2 종료** |

무납땜은 편의가 아니라 **리스크 관리**다.

## 1. Phase 1 — 납땜이 필요한 곳

| 대상 | 납땜 | 비고 |
| :--- | :---: | :--- |
| MechDog 본체 | 없음 | 순정 조립 |
| 킷 확장 모듈 (WonderEcho · MP3 · 초음파 · 터치) | **없음** | JST 커넥터로 꽂는다 |
| 눈 LED | 없음 | 초음파 센서에 내장 (OI-12 닫힘) |
| **XIAO 전원** | **0회** | USB-C 로 급전 |

### XIAO 전원

**개발 중에는 PC 의 USB-C 에 꽂는다.** 시리얼 로그를 함께 보며 디버깅할 수 있고 전원 문제가 발생하지 않는다.
시연에서는 **보조배터리를 USB-C 로 연결**한다.

| 방식 | 납땜 | 무게 |
| :--- | :---: | ---: |
| **USB-C 보조배터리** ← 채택 | **0회** | 40~120 g |
| BAT 패드에 LiPo 직결 | XIAO당 1회 | ~20 g |

> **LiPo 직결은 무게 초과로 판정될 때만 되돌아가는 대안이다.** 그 경우 벌크 커패시터(470~1000µF)가
> 함께 필요하고(Wi-Fi 송신 피크의 브라운아웃 방지, PRD 2.4), 납땜이 발생한다.
> 되돌아갈 때는 패드에 셀을 직접 붙이지 말고 **JST 피그테일을 붙여 납땜을 1회로 끝낸다.**
>
> ⚠️ **JST PH 2.0 의 극성은 판매처마다 다르다.** 연결 전 멀티미터로 확인한다.
> XIAO 에는 역극성 보호가 없어 즉시 파손된다.

## 2. Phase 2 — LiDAR 노드 [P2]

### 2.1 LD19 인터페이스 (데이터시트 확정)

**포트가 하나뿐이며 전원과 데이터를 겸한다.**

```
LD19 본체
  └─ ZH1.5T-4P 소켓  ← 구멍이 이것 하나
        ├── Pin 4  P5V   전원 +   (4.5 ~ 5.5 V)
        ├── Pin 3  GND   전원 −
        ├── Pin 2  PWM   모터 제어 입력
        └── Pin 1  Tx    데이터 출력 (0 ~ 3.3 V, 단방향)
```

| 항목 | 값 |
| :--- | :--- |
| 커넥터 | **ZH1.5T-4P (1.5mm 피치)** — PH2.0(2.0mm) 아님 |
| Baud | 230400 |
| 로직 레벨 | 3.3V TTL → ESP32 직결 가능 |
| 통신 방향 | **단방향(Tx만)** — 명령을 넣을 일이 없다 |
| 스캔 | 10 Hz · 12 m |

> **PWM 은 접지하면 된다.** 데이터시트: *PWM 핀을 접지하면 내부 속도 제어가 기본 적용되어 10Hz 로 회전한다.*
> **PWM 신호를 만들 필요가 없고 ESP32 핀을 추가로 쓰지 않는다.**

> **5V 허용 범위가 4.5~5.5V** 이므로 보조배터리 USB 출력(5V)이 그대로 들어간다. **승압 모듈이 필요 없다.**

### 2.2 무납땜 배선 — 직결 (채택)

**LiDAR 전원을 ESP32 의 `5V` 핀에서 뽑는다.** ESP32 DevKit 은 USB 로 받은 5V 를 그 핀으로 내보내므로
배터리에서 따로 뽑을 필요가 없다.

그리고 **DevKit 에는 `GND` 핀이 2~3개 있다.** 따라서 분기가 필요 없고, 하네스 4선을 핀에 하나씩 꽂으면 된다.

```
      보조배터리 ──USB── ESP32 DevKit (WROOM-32)
                              │
                LD19 ─[ZH1.5]─ 케이블 ─ 낱개 암 듀폰 4개
                                          │
                    ┌─────────────────────┼──────────┬──────────┐
                  Pin4 P5V            Pin3 GND    Pin1 Tx   Pin2 PWM
                    │                     │           │         │
                 ESP32 5V            ESP32 GND    GPIO16    (미연결)
```

| LD19 핀 | ESP32 핀 | 위치 |
| :--- | :--- | :--- |
| Pin4 `P5V` | **`5V`** | 왼쪽 맨 아래 (`5VD`) |
| Pin3 `GND` | **`GND`** | GND 3개 중 아무거나 |
| Pin1 `Tx` | **`GPIO16`** (UART2 RX) | 오른쪽 |
| Pin2 `PWM` | **미연결** | 데이터시트: 미연결·Hi-Z 시 내부 제어 10Hz |

**실제로 연결하는 것은 3선이다.**

#### RX 핀 선택 — `U0RXD`(GPIO3)를 쓰지 않는다

GPIO1/GPIO3 은 **USB 시리얼**용이다. 여기에 LiDAR 를 물리면 **펌웨어 업로드가 막히고 로그가 깨진다.**
ESP32 는 UART 가 3개이므로 **UART2(GPIO16 RX / GPIO17 TX)** 를 쓴다.

| 피해야 할 핀 | 이유 |
| :--- | :--- |
| **GPIO6~11** | **플래시 메모리 연결. 사용 금지** |
| GPIO1 / GPIO3 | USB 시리얼 |
| GPIO0 / GPIO2 / GPIO12 / GPIO15 | 스트래핑 핀 — 부팅 모드에 영향 |

GPIO16 대신 GPIO25·26·27·32·33 도 자유롭게 쓸 수 있다.

> ⚠️ **WROVER 버전은 GPIO16·17 을 PSRAM 이 점유한다.** 상품명에 `WROOM` 을 확인하고,
> WROVER 라면 RX 를 GPIO25 등으로 옮긴다.

#### 케이블 요구 조건 — 낱개 암 단자여야 한다

ESP32 핀은 **수(male)** 이므로 상대가 **암(female)** 이어야 하고, 목적지 핀이 서로 떨어져 있으므로
**낱개 4개**여야 한다.

| 케이블 끝 형태 | 직결 가능 |
| :--- | :---: |
| **낱개 암 듀폰 ×4** ← 채택 | ✅ |
| 4핀 일체형 암 하우징 | ❌ 핀이 나란해야 하는데 흩어져 있다 |
| 벗겨진 선 | ❌ 아래 2.2.1 예비 경로 |

> ⚠️ **피치 확인이 필수다.** 사진으로는 ZH(1.5mm)·GH(1.25mm)·PH(2.0mm)·XH(2.54mm)를 구분할 수 없다.
> **스펙에 `ZH` 또는 `1.5mm` 표기가 있는지 확인한다.**

> ⚠️ **선 색이나 하우징 핀 번호만으로 기능을 판단하지 않는다.** 현재 물리 순서를 1차 출처로 확정하지
> 못했으므로 LiDAR 기판의 `TX/PWM/GND/P5V` 실크를 직접 대조하고, 멀티미터로 전원선을 확인한다.
> 전원선을 잘못 연결하면 LiDAR가 파손될 수 있다.

### 2.2.1 예비 경로 — 브레드보드

케이블 피치가 맞지 않거나 낱개 암 단자를 구하지 못한 경우, **벗겨진 선 하네스 + 25핀 미니 브레드보드**로
우회한다. 같은 열(가로 5홀)에 꽂으면 연결된다.

| 열 | 브레드보드에 꽂는 것 | 점퍼가 가는 곳 |
| :---: | :--- | :--- |
| 1 | 하네스 `P5V` | ESP32 `5V` |
| 2 | 하네스 `GND` | ESP32 `GND` |
| 3 | 하네스 `Tx` | ESP32 `GPIO16` |

이때는 **암-수** 듀폰 점퍼가 필요하다 — 암이 DevKit 수핀에, 수가 브레드보드 구멍에 들어간다.

> **직결을 1순위로 두는 이유는 견고성이다.** 브레드보드는 선을 구멍에 끼우는 방식이라 **보행 진동으로 빠진다.**
> 듀폰 하우징은 핀을 감싸 물고, 접점 수도 절반이다. 브레드보드로 가게 되면 **조립 후 글루건으로
> 꽂힌 부위를 굳힌다.**
>
> **ESP32 DevKit 을 브레드보드에 꽂지 않는다.** 25핀 미니는 길이가 부족하고, DevKit 은 폭이 넓어
> 양옆 구멍이 모두 덮인다. 브레드보드는 선 이음매로만 쓰고 DevKit 은 밖에 둔다.

### 2.3 중계 MCU — ESP32-DevKitC V4 (확정)

| 항목 | 확정 사양 |
| :--- | :--- |
| 모듈 | **ESP32-WROOM-32E** — WROVER 아님 → **GPIO16·17 자유** |
| 핀 구성 | **38핀**, DevKitC V4 와 동일한 핀맵 |
| USB | **USB-C** (micro-USB 호환 아님) |
| 핀헤더 | **기장착 출하** — 무납땜의 전제 |
| 입력 전압 | 5V → `5V` 핀에서 LiDAR 급전 |
| 부가 | **3D STEP 파일 제공** → 마스트·홀더 설계에 활용 |

#### C3 SuperMini 를 쓰지 않는 이유

| | ESP32-C3 SuperMini | **ESP32-DevKitC V4** |
| :--- | :--- | :--- |
| 핀헤더 | 낱개 동봉 → **납땜** | **기장착 출하** |
| 무게 | ~3 g | ~10 g |
| 코어 | 싱글 | **듀얼** — UART 수신과 Wi-Fi 송신을 분리 가능 |

**무게 페널티 7g 으로 납땜이 0 이 된다.** LiDAR 50g · 보유 보조배터리 100~120g 옆에서 7g은 작지만,
최종 판단은 V-3 부하 실측으로 한다.

> **USB-C 로 확정되어 케이블이 정리된다.** XIAO ESP32S3 도 USB-C 이므로 **같은 A↔C 케이블 2개**면 되고,
> 대부분 보유분으로 해결된다.

### 2.4 왜 XIAO 겸임이 아니라 별도 MCU 인가 (OI-7 닫힘)

| # | 근거 |
| :-- | :--- |
| ① | **XIAO 가 이미 바쁘다.** VGA 15fps 캡처·JPEG 인코딩·Wi-Fi 송신 중에 230400 baud 연속 스트림을 받아야 한다. 대역폭이 아니라 **타이밍**이 문제이며, UART 버퍼를 놓치면 스캔이 깨진다 |
| ② | **전원이 서로를 흔든다.** LiDAR 모터 부하가 XIAO 공급을 흔들면 영상이 끊긴다 |
| ③ | **배선이 로봇을 가로지른다.** LiDAR 는 마스트 위, XIAO 는 몸통이다 |
| ④ | **고장 격리가 사라진다.** 겸임하면 하나가 죽을 때 둘 다 죽는다 |

**비용 차이는 로봇별 MCU 1대, 총 2대다.** 겸임해도 LiDAR 전원은 어차피 분리해야 한다.

### 2.5 D500 키트 동봉품을 버리지 않는다

| 동봉품 | 역할 |
| :--- | :--- |
| **USB 어댑터 보드** (micro-USB) | 5V 공급 + Tx→USB 변환. **PC 직결 전용** |
| **리본 케이블** (양쪽 커넥터) | LiDAR ↔ 어댑터 연결 |
| USB 케이블 | micro-USB ↔ USB-A |

**리본 케이블과 ZH 하네스는 대체 관계가 아니다.** 리본은 PC 직결(1·2단계)용, 하네스는 ESP32 연결(3단계)용이며,
상황에 따라 바꿔 꽂는다.

> **어댑터 보드는 프로젝트 내내 디버깅 기준선이다.** 무선 구성에서 스캔이 끊기면 어댑터로 PC 에 직결해 본다.
> PC 에서 나오면 배선·펌웨어 문제, PC 에서도 안 나오면 LiDAR 문제로 **원인이 즉시 반으로 줄어든다.**

### 2.6 전류 리스크 — 측정으로 판정한다

| 부하 | 소비 |
| :--- | ---: |
| LD19 | ~200 mA |
| ESP32 DevKit | ~200 mA |
| **DevKit `5V` 핀 경로 합계** | **~400 mA** |
| XIAO (별도 포트) | 220 mA |

**배터리 쪽은 문제가 없다.** 포트별로 220mA / 400mA 로 나뉘고 5,000mAh 급은 2A 이상 출력한다.
**주의할 지점은 용량이 아니라 경로다** — LiDAR 가 DevKit 의 `5V` 핀을 거치므로
**DevKit 의 USB 커넥터와 내부 VBUS 트레이스에 400mA 가 몰린다.**

#### 폴리퓨즈는 끊어지지 않는다 — 저항이 올라간다

일부 DevKit 보드에는 VBUS 에 **500mA PPTC 폴리퓨즈**가 달려 있다. 400mA 는 마진이 얇다.

> ⚠️ **PPTC 는 정격 초과 시 차단되는 것이 아니라 저항이 증가한다.** 따라서 증상이
> *"완전 정지"* 가 아니라 **"간헐적 리셋 · 스캔 끊김 · 원인 불명의 불안정"** 으로 나타난다.
>
> **그러므로 "문제가 생기면 그때 분리한다" 는 위험하다.** 증상만으로는 원인이 배선인지 펌웨어인지
> Wi-Fi 인지 구분되지 않아 며칠을 태울 수 있다.

#### 판정 — 멀티미터로 `5V` 핀 전압을 측정한다

| 조건 | 판정 |
| :--- | :--- |
| LiDAR 미연결 | 약 5.0V — 기준값 기록 |
| **LiDAR 연결 후 4.5V 이상** | ✅ **통합 유지** |
| **4.5V 미만 또는 변동이 큼** | ❌ **분리 필요** |

**LD19 공급 전압 허용 하한이 4.5V** 다(2.1). 그 위면 정상 동작하고 아래면 불안정해진다.
**애매한 증상을 기다리지 않고 숫자로 갈린다.** 멀티미터는 이 때문에도 필수다(7.3).

#### 분리 구성 — 납땜은 여전히 0

```
보조배터리 ┬─ 포트1 ─USB─→ XIAO
           │
           └─ 포트2 ─[USB 분배]─┬─USB─→ ESP32 DevKit      (200mA)
                                └─[USB 전원 케이블]─→ 브레드보드 → LD19 (200mA)
```

**DevKit 경로에 200mA 만 남는다.** 그리고 **같은 배터리에서 나오므로 GND 는 여전히 공통**이라
UART 성립 조건이 유지된다(3.3).

| 추가 부품 | 가격 |
| :--- | ---: |
| USB 분배 케이블 (1→2) | 2,000원 |
| USB 전원 케이블 (한쪽 낱개선) | 2,000원 |

**둘 다 이미 구매 목록에 보험으로 들어가 있다**(7.1·7.2). 발주가 1회이므로 어차피 담아야 한다.

#### 채택하지 않은 대안

| 방법 | 이유 |
| :--- | :--- |
| 폴리퓨즈 없는 보드 선택 | **상품 페이지에 정격이 표기되지 않는다.** 사전 확인이 불가능하다 |
| 벌크 커패시터로 흡수 | 순간 부하에는 도움이 되지만 **400mA 지속에는 무효**다. PPTC 는 지속 전류에 반응한다 |
| PWM 으로 LiDAR 감속 (10Hz → 6Hz) | 모터 전류는 줄지만 **스캔 주기가 느려져 SLAM 정합 품질이 떨어진다.** 최후 수단 |

### 2.7 별도 IMU 를 담지 않는 이유

**MechDog 에 IMU 가 내장되어 있고**, 텔레메트리 스키마에 이미 `imu: {pitch, roll, yaw}` 가 있다.
별도 MPU6050 은 **순정 IMU 접근이 불가한 경우의 보험**이었으나, 담지 않기로 한다.

**별도 IMU 를 달면 오히려 불리하다.** LiDAR 의 기울기를 정확히 재려면 IMU 가 **LiDAR 와 같은 강체**,
즉 마스트 위에 붙어야 한다.

| 그 대가 |
| :--- |
| 무거운 것을 또 높이 올린다 → 무게중심 불리 |
| I2C 2선 + 전원 배선 추가 → 무납땜 구성이 복잡해진다 |
| 축 정렬 캘리브레이션 작업 추가 |

**Stop-and-Scan(DR-7)이면 스캔 시점에 진동이 거의 없으므로 몸통 IMU 의 근사치로 충분하다.**

#### 순정 IMU 접근도 불가한 경우 — 소프트웨어로 대체한다

| 대상 | 대체 수단 |
| :--- | :--- |
| **FR-6.3 스캔 유효성 필터** | 기울기 각도 대신 **스캔 통계**로 판정 — 무효 측정점 비율 급증(빔이 바닥·천장을 때린다), 이전 스캔과의 정합 잔차 급증 |
| **FR-6.4 odometry prior** | 직진 성분은 gait odometry 실측 계수로 확보. **회전량은 Stop-and-Scan 의 큰 겹침에 기대어 scan matching 이 추정**한다 |

**arc 조향(DR-11)이 여기서 유리하게 작용한다** — 제자리 선회는 겹침이 적어 정합이 어렵지만,
조금씩 이동+회전하는 arc 는 겹침이 커서 정합에 유리하다.

**품질은 떨어지지만 성립한다.** M0 에서 순정 IMU 접근성만 확인한다.

## 3. 전원 용량 산정

기준은 **로봇 본체가 먼저 방전된다**는 것이다. 순정 2S 로 30~60분 추정(OI-4), 시연은 10분이다.

| 부하 | 평균 |
| :--- | ---: |
| XIAO (카메라 + Wi-Fi) | 200~250 mA |
| LD19 | ~200 mA |
| ESP32 DevKit | ~150~250 mA |
| **합계** | **~600 mA** |

보조배터리 정격은 3.7V 셀 기준이며 5V 승압 손실로 **실사용은 정격의 60~70%** 다.

| 정격 | 5V 기준 실사용 | 600mA 기준 | 무게 |
| ---: | ---: | ---: | ---: |
| 2,000 mAh | ~1,300 mAh | 2시간 | 40~50 g |
| 3,000 mAh | ~2,000 mAh | 3시간 | 60~70 g |
| **5,000 mAh** ← **보유분 사용** | **~3,300 mAh** | 5시간+ | **100~120 g** |

> **보유분(5,000mAh · 2구)을 쓴다.** 용량은 과하지만 3,000mAh 로 바꿔 얻는 이득이 40~60g 뿐이고,
> 탑재 여력(약 600g)에 비하면 무의미하다. **신규 구매 시에만 3,000mAh 급을 고른다.**

### 3.1 배터리를 하나로 통합하는 것이 무게중심에 유리하다

| 구성 | 무거운 것의 위치 |
| :--- | :--- |
| 배터리 2개 | 몸통 + **마스트 위** ❌ |
| **배터리 1개** | **몸통 하부에 집중** ✅ |

**4족 보행은 절대 무게보다 무게중심 높이에 훨씬 민감하다**(측위 문서 6절). 배터리를 통합해 몸통 낮은 곳에
붙이고 선만 위로 올리면 마스트에는 LiDAR 만 올라간다. 대가는 고장 격리 상실이지만,
10분 시연에서 카메라가 죽으면 어차피 시연이 성립하지 않으므로 실질 손해는 제한적이다.

### 3.2 포트 구성 — 3구가 필요하지 않다

**GND 를 공유해야 하는 것은 LD19 과 ESP32 뿐이다.** XIAO 는 Wi-Fi 로만 통신하므로 누구와도 GND 를 공유할 필요가 없다.

```
보조배터리 ┬──→ ESP32 DevKit ──→ LD19   (GND 공통 필요 ✅)
           └──→ XIAO                    (독립 무관)
```

**2구면 충분하다.** 부족하면 USB 분배 케이블(약 2,000원)로 늘린다.

> ⚠️ 보조배터리의 **USB-C 포트가 입출력 겸용**인 제품이 많고, 그 경우 다른 포트와 배타적이거나 출력이 되지 않는다.
> **가진 제품으로 두 부하를 동시에 켜보는 것**이 가장 빠른 확인이다.

### 3.3 GND 를 공유해야 하는 이유

전원은 기기 안에서 닫힌 회로이므로 남과 무관하다. 그러나 **신호선은 두 기기를 잇는 새 경로**이며
전류가 돌아올 길이 필요하다.

더 근본적으로, **`3.3V` 는 GND 를 기준으로 한 값이다.** 두 기기의 GND 기준이 다르면
LD19 이 내보낸 "3.3V" 를 ESP32 가 몇 V 로 읽을지 정의되지 않는다.

본 구성에서는 **LiDAR 전원을 ESP32 의 5V·GND 핀에서 뽑으므로 GND 가 자동으로 공통**이다.
배터리를 분리하면 GND 선을 직접 이어야 하며, 그 한 선을 빠뜨리는 것이 가장 흔한 실패 원인이다.

## 4. 마스트와 차폐 — 무게보다 이쪽이 제약이다

탑재 여력이 약 600g 으로 확인되어(RISK-02, 잠정) **무게는 1순위 제약이 아니다.**
대신 **차폐**가 올라온다.

2D LiDAR 는 **수평면 하나를 360° 로 훑는다.** 그 평면에 걸치는 것은 모두 벽으로 인식된다.

```
              ╔═══════╗  ← 스캔면
              ║ LD19  ║ ──────────────→ 이 높이를 훑는다
              ╚═══╤═══╝
                  │
      ┌───────┐   │
      │ESP32  │◀──┼── 이것이 스캔면보다 높으면
      │ 메인  │   │     전방이 통째로 막힌다
      └───────┘ ┌─┴──┐
   ┌────────────┤배터리│────┐
   │        몸통          │
   └──┬──┬────────┬──┬────┘
```

| 기준 |
| :--- |
| **스캔면이 몸통 최고점(ESP32 메인보드 · 초음파 모듈)보다 위에 있어야 한다** |
| 필요 높이는 **실측으로 정한다** — OI-2 에 차폐 기준 높이 항목을 포함한다 |

**전방 차폐가 치명적이다.** 앞이 안 보이면 SLAM 도 회피도 성립하지 않는다.

### 4.1 트레이드오프

| 마스트를 | 결과 |
| :--- | :--- |
| 높이면 | 차폐 해소 ✅ / 무게중심 상승 ❌ |
| 낮추면 | 무게중심 유리 ✅ / 전방 차폐 ❌ |

### 4.2 완화책

| # | 방법 |
| :-- | :--- |
| ① | **차폐 각도를 마스킹한다.** 고정 차폐 구간을 버리고 나머지로 정합한다. `slam_toolbox` 는 부분 시야로도 동작한다 (예: 유효 시야 240°) |
| ② | **LiDAR 를 앞쪽에 배치한다.** 몸통·배터리가 뒤에 있으므로 후방만 가려진다. 순찰 로봇은 전방이 중요하므로 맞는 방향이다. 단 무게가 앞으로 쏠려 보행 균형에 영향을 준다 |

### 4.3 보조배터리를 LiDAR 받침으로 쓰지 않는다

| # | 이유 |
| :-- | :--- |
| ① | **무게중심 최악** — 가장 무거운 것을 가장 높이 올린다 |
| ② | **흔들린다** — 케이스가 매끄럽고 유연해 보행 진동에 LiDAR 가 함께 흔들린다. **스캔면이 기울면 벽이 사선으로 찍힌다** (DR-7 이 다루는 왜곡을 증폭한다) |
| ③ | **높이 조절 불가** — 배터리 두께가 마스트 높이를 결정해버린다 |

**배터리는 낮게, LiDAR 는 별도 마스트로 올린다.**

## 5. 배선 실무 — 걸어다니는 로봇이라는 점

납땜보다 **이쪽이 실제 고장 원인이 된다.** 4족은 다리가 크게 움직이고, 선 하나가 걸리면 전도로 이어진다.

| 규칙 |
| :--- |
| 몸통 → 마스트 배선은 **한 다발로 묶어 한 경로**로 올린다 |
| **다리 관절 근처를 지나가지 않게** 몸통 중앙 상부로 우회한다 |
| 케이블 타이·스파이럴 튜브로 고정한다. **늘어진 구간을 만들지 않는다** |
| 커넥터에 장력이 걸리지 않게 여유를 두되 처지지 않게 한다 |
| **브레드보드와 듀폰 점퍼는 진동으로 빠진다.** 조립 후 글루건·절연테이프로 꽂힌 부위를 고정한다 |

## 6. 도입 순서 — 변수를 하나씩 넣는다

LiDAR 를 사더라도 처음부터 무선화하지 않는다. **1·2단계는 D500 키트 동봉품만으로 추가 구매 없이 수행한다.**

| 단계 | 하는 일 | 납땜 | 확인되는 것 |
| :---: | :--- | :---: | :--- |
| **1** | LiDAR + 동봉 어댑터 → **PC 직결**. rviz2 에 스캔 표시 | 0 | LiDAR 정상 여부 · 드라이버 동작 |
| **2** | 로봇에 얹고 **무게 · 차폐 · 마스트 높이 측정** | 0 | 게이트 통과 여부 · 마스트 설계값 |
| **3** | 무선화 — ESP32 중계 | 0 | |

**1단계에서 LiDAR 와 드라이버가 정상임을 확인**한 뒤 넘어가면, 이후 실패의 원인이 배선인지 LiDAR 인지 즉시 격리된다.

> ⚠️ **2단계 무게 측정 시 최종 구성의 무게를 흉내내야 한다.** 1·2단계에서 로봇에 올라가는 것은
> LiDAR + 리본 케이블뿐이며, 어댑터와 PC 는 밖에 있다. 최종 구성에서는 아래가 추가된다.
>
> | 최종에 추가되는 것 | 대략 |
> | :--- | ---: |
> | ESP32 DevKit | ~10 g |
> | **보조배터리 (5,000mAh)** | **100~120 g** |
> | 케이블 · 점퍼 · 테이프 | ~15 g |
> | **합계** | **약 125~145 g** |
>
> LiDAR(50g)와 마스트(20~40g)를 더하면 **최종 구성은 약 200~235 g** 이다.
>
> **그만큼 더 얹은 상태로, 마스트 높이에서** 걷혀본다. 안 그러면 통과했다고 착각하고 조립한 뒤에 실패한다.

### 7.2 예비 — LiDAR 노드가 2대이므로 2대분을 담는다

발주 기회가 1회이므로, 없을 때 막히는 비용이 부품값보다 크다.
**아래는 로봇에 남는 부품이므로 노드 수만큼 필요하다** — 도구(멀티미터)와 성격이 다르다.

#### 멀티미터는 LiDAR 직결 전 필수다

기판 실크로 기능을 확인한 뒤에도 전원선과 DevKit `5V` 출력이 정상인지 측정한다. 스캔 유실률은
전압 문제를 사후에 보여줄 뿐 역결선 파손을 예방하지 못한다. LiPo 구성으로 되돌릴 경우에는 MT3608
출력 조정에도 같은 멀티미터를 사용한다.

> **있으면 추측이 사라진다** — 위 대안들은 간접적이고 시간이 걸리는데 멀티미터는 5초에 답을 준다.
> **없어도 진행된다.** 1~2만원의 판단이다.

### 7.3.1 ArUco 마커는 왜 인쇄물이어야 하는가

**ArUco 는 물리적으로 존재해야 한다.** 흑백 사각 패턴을 카메라가 촬영해 ID 를 읽는 방식이다.
**Track B 의 ARCore 앵커와 혼동하기 쉬우나 성질이 완전히 다르다**(측위 문서 4절).

| 용도 | 좌표·앵커로 대체 |
| :--- | :--- |
| **FR-8.0 구역 식별** | **Phase 2 에서 가능** — 측위가 좌표를 주면 마커가 불필요해진다. Phase 1 에는 측위가 없으므로 필요하다 |
| **FR-10.1 사원증** | **불가** — 좌표는 *"여기가 어디인가"*, 사원증은 *"당신이 누구인가"* 다. 대안(얼굴 인식·RFID·QR)은 모두 더 비싸거나 결국 인쇄물이다 |

## 8. 발주 전 확인 목록

| ✔ | 항목 | 왜 |
| :---: | :--- | :--- |
| ~~①~~ | ~~LiDAR 모델명~~ | ✅ **확정** — FHL-LD19. D300/D500 표기가 섞여 있으나 LD19·STL-19P의 커넥터 규격·통신 조건은 같다. **물리 핀 순서는 별도 미확정이므로 기판 실크를 대조한다** |
| ② | **케이블이 ZH (1.5mm) 인지** | GH(1.25)·PH(2.0)·XH(2.54)는 맞지 않는다. 사진으로 구분 불가 — **스펙 표기 확인** |
| ②' | **케이블 끝이 낱개 암 듀폰 4개인지** | 4핀 일체형 하우징은 직결에 쓸 수 없다 (2.2) |
| ~~③~~ | ~~핀헤더 기장착 · WROOM-32~~ | ✅ **확정** — ESP32-DevKitC V4 (WROOM-32E · 38핀 · USB-C · 핀 기장착) |
| ~~④~~ | ~~DevKit USB 포트~~ | ✅ **확정** — USB-C. XIAO 와 같은 A↔C 케이블 |
| ⑤ | **보조배터리 다중 포트 동시 출력** | 보유품으로 확인 가능 |
| ⑥ | **하네스 길이 20cm 이상** | 마스트↔몸통 거리. 10cm 는 부족할 수 있다 |
| ⑦ | 25핀 브레드보드 **뒷면 접착층** | 없으면 글루건·양면테이프 필요 |
| ⑧ | **조립 후 DevKit `5V` 핀 전압 측정** | LiDAR 연결 상태에서 **4.5V 이상**인지 확인. 미만이면 전원 분리 (2.6) |

> ⚠️ **하네스 선 색으로 핀을 판단하지 않는다.** 색은 제조사가 임의로 정한다.
> LiDAR 기판의 `TX/PWM/GND/P5V` 실크를 직접 대조하고 멀티미터로 전원선을 확인한다.
> **검증되지 않은 핀 순서 표를 사용하지 않는다.** 전원선을 잘못 연결하면 LiDAR가 파손될 수 있다.

### LiPo 구성으로 되돌릴 경우에만 필요한 절차

무게 초과로 보조배터리를 포기하면 **LiPo + MT3608 + TP4056** 구성이 되고 납땜이 약 12~15점 발생한다.
이때 **순서를 지키지 않으면 LiDAR 가 파손된다.**

```
① MT3608 에 배터리만 물린다        (LiDAR 미연결)
② 멀티미터로 출력을 재서 5V 로 맞춘다
③ 전원을 끊는다
④ 그 다음에 LiDAR 를 연결한다
```

MT3608 은 **가변저항으로 출력이 조절되는 모듈**이며 출하 상태가 5V 라는 보장이 없다.
②를 건너뛰고 바로 연결하는 것이 가장 흔한 사고다.
