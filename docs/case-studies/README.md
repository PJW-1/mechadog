# 사례 연구

실기에서 드러난 문제를 어떻게 좁히고, 무엇을 재고, 어떻게 고쳤는지를 한 건씩 정리한 문서입니다. 각 문서는 **증상 → 가설과 배제 → 측정 → 원인 → 수정 → 검증 → 남은 한계** 순서를 따르고, 수치마다 원문(ADR, 측정 기록, 코드, 테스트)으로 링크를 겁니다.

| # | 사례 | 한 줄 요약 |
| :-- | :--- | :--- |
| 1 | [명령 타임아웃 300ms → 600ms](01-command-timeout.md) | Host 는 제때 보냈지만 2.4GHz 무선 구간 지연으로 로봇이 스스로 래치했고, 시리얼 로그로 원인을 확정한 뒤 온보드 워치독과 설정 검증 상한을 함께 600ms 로 옮겼습니다. |
| 2 | [10fps 추론이 진짜 검출의 절반 이상을 놓친 문제](02-person-gate-time-window.md) | 실기 343프레임의 연속 구간 분석에서 10fps 가 진짜 검출 10개 중 4개만 확정해, 추론률을 25fps 로 올리고 판정을 «300ms 창 안 3회» 로 바꾸고 불가능한 설정을 로더가 거부하게 했습니다. |
| 3 | [반향된 상태값 때문에 Host 가 스스로를 잠글 수 있었던 문제](03-echoed-state-self-lock.md) | 로봇이 Host 가 보낸 `state` 를 되돌려 보내므로 그 값으로 해제를 막으면 Host 가 영구히 잠기며, 반향되지 않는 `safety_latched` 와 `obstacle` 만 판단에 쓰도록 바꿨습니다. |
| 4 | [로봇 I²C 경유 음성 파형 중계가 불가능했던 사례](04-i2c-voice-relay.md) | 로봇 I²C 브리지 `0x34` 를 직접 읽고 써서 명령 id 만 오간다는 것을 확인했고, 듣기는 XIAO 마이크로, 말하기는 MP3 모듈로 나눴습니다. |
