# WBS 3.5.4 실기 — TRACK 락온 (2026-09-18 · mechdog-01)

> ⚠️ **이 기록은 `mechdog-01` 한 대의 것이다.** 아래의 선회 비대칭·데드밴드·드리프트는
> 개체별 서보 오프셋에서 나오므로 **기체마다 방향도 크기도 다르다**([HARDWARE 3절](../../../docs/HARDWARE.md)).
> `mechdog-02` 이하는 각자 다시 재야 하며 이 값을 복사하면 안 된다.

도구는 런타임 자체다 — `python -m host.runtime --device mechdog-01 --dashboard-port 8000`.
순찰·추종은 관제 화면의 `/api/command/patrol`·`/api/command/reset` 으로 넣었고, 사람이 카메라
앞에서 좌우로 이동했다. 원자료는 같은 폴더의 `track_commands.txt`·`track_summary_1hz.txt`·
`track_events.txt` 이며 런타임 로그는 `logs/mechdog-01.jsonl`(커밋하지 않는다)이다.

## 시험 전 고친 것 둘

| | 문제 | 조치 |
| :--- | :--- | :--- |
| 카메라 펌웨어 | `/orient` **404** · 루트 응답에 `rot` 필드 없음 — 2026-09-15 에 생긴 경로인데 그 뒤 XIAO 를 플래시하지 않았다. 런타임이 매 기동 `orientation_apply_failed` 를 남기고 조용히 넘어가고 있었다 | 저장소 `firmware_xiao_vision` 을 그대로 재플래시 (esp32 2.0.17 · `PSRAM=opi` · 758KB). `/orient` 200, `rot` 필드 복귀 |
| 장착 방향 | 화면이 **상하 반전**. `mount_rotation` 이 `0` 이었다 | `config/devices/mechdog-01.local.yaml` 에 `vision.mount_rotation: 180`. **전역이 아니라 개체 프로파일에 둔다 — 장착 방향은 기체별 물리 사실이다** |

락온이 대상 **반대쪽**으로 조향했다. 개체 주소도 DHCP 가 바꿔 달아 09-14 기록과 반대였다
(로봇 `.102` · 카메라 `.101`, 로봇이 보낸 `device_id` 의 MAC 으로 확인).

## 좌우가 갈렸다 — **오른쪽을 못 쫓는다**

`track_dev_px_avg`(절대값, 1초 요약)의 추이다.

| 방향 | 편차 추이 | 결과 |
| :--- | :--- | :--- |
| 왼쪽 | 183 → 156 → 124 → 38 → **11** px | **약 12초에 데드존 진입** |
| 오른쪽 | 158 → 180 → 215 → 228 → 233 → **205** px | **49초 동안 한 번도 못 들어감** |

그동안 `track_angle_deg_avg` 는 **7~13.8°** 로 계속 나가고 있었다. 즉 **명령은 쉬지 않고
오른쪽으로 돌라고 했는데 기체가 따라오지 않았다.** 육안 관찰도 같다 — *"오른쪽으로 아예
회전을 못 한다"*.

### 원인 — 이미 측정돼 있던 상수 둘이 겹친다

`config/devices/mechdog-01.yaml` 의 2026-09-11~12 실측이다.

```
우선회 이득   0.228 °/s per deg      효과 = 0.228 x (|각도| - 3.3)
우 데드밴드   3.3°
좌선회 이득   6.8 °/s @ 20° = 0.34 °/s per deg
직진 요 드리프트  좌로 1.0 °/s       (걷기만 해도 왼쪽으로 휜다)
```

실제로 나간 명령에 대입하면 —

| 명령 | 조향 효과 | 드리프트 | 실제 회전 |
| ---: | ---: | ---: | ---: |
| +0.77° 좌 | 0 (데드밴드 안) | 좌 1.0 | **좌 1.00 °/s** |
| +3.90° 좌 | 좌 0.20 | 좌 1.0 | **좌 1.20 °/s** |
| −8.40° 우 | 우 1.16 | 좌 1.0 | **우 0.16 °/s** ← 10초에 1.6도 |
| −12.39° 우 | 우 2.07 | 좌 1.0 | **우 1.07 °/s** |

**왼쪽은 명령이 데드밴드에 먹혀 0 이 돼도 드리프트가 대신 돌려주고, 오른쪽은 드리프트를
먼저 갚느라 남는 것이 없다.** 프로파일 주석이 이것을 미리 적어 두었다 —
*"작은 편차가 만드는 3도 이하 명령은 아무 일도 하지 않는다. 비례 제어의 저역이 통째로 죽어
있다는 뜻이므로 그 설계에 반영해야 한다."*

### 조치

`gait_calibration.straight_bias_deg`(−8.0)는 **이미 실측돼 있었고 쓰는 곳이 없었다.**
락온이 걷는 동안 이 값을 조향에 더하도록 했다. 드리프트가 상쇄되고, 총 명령이 데드밴드
밖으로 밀려나 **비례 제어의 죽은 저역까지 함께 살아난다.** 값이 없는 기체는 보정하지 않는다.

⚠️ **재검증이 필요하다.** 이 보정은 위 실측 상수에 근거한 계산이며, 보정 뒤의 좌우 대칭을
실기로 확인하지 않았다. `2.2.3` 에서 카메라를 얹은 구성으로 좌우를 다시 잴 때 함께 본다.

## 함께 드러난 것

**① 검출이 자주 끊긴다** — 공백 **38회 · 중앙값 956ms**(최소 11ms · 최대 18.7초). 점수가
낮아지는 게 아니라 `hits=0 score=0.0` 으로 **아예 사라진다.** 지시가 `cmd_timeout_ms`(300ms)
보다 낡으면 `TrackSequence` 가 **정지를 보내므로**(설계대로 — 안 보내면 로봇이 직전 각도로
계속 돈다) 추종이 중간중간 멈춘다. 사람 몸이 프레임 경계에 잘리면 특히 심하며, 이 대응은
`3.5.7` 단계적 자세 상승 시퀀스 소관이고 아직 미구현이다. 기체 pitch 가 12~39° 로 앞이
내려가 있어 카메라가 바닥을 보는 것도 겹친다.

**② 명령 링크 여유가 줄었다** — 카메라를 로봇에 얹고 25fps VGA 를 같은 AP 로 쏘기 시작한
뒤 `last_cmd_age_ms` 중앙값이 **13.1ms → 88.5ms** 로 올랐고(최대 3,575ms), 3초를 넘겨
`LINK_LOST` 페일세이프가 **2회** 걸렸다.

⚠️ README 의 *"XIAO VGA 25fps 수신 중에도 명령 RTT 평균 3.2ms, 통신은 병목이 아니다"*
(2026-09-09)와 다르다. 그때는 카메라가 로봇에 실려 있지 않았다. **한 번의 관측이므로
단정하지 않는다** — 카메라를 얹은 구성에서 다시 재야 한다.

## 미확정으로 남긴 것

- **보정 뒤 좌우 대칭** — 계산으로만 세웠다. 실기 확인은 `2.2.3` 에서.
- **좌 데드밴드** — 미측정이다. 위 표의 왼쪽 값은 우 데드밴드(3.3°)를 빌린 추정이다.
- **선회율 재측정** — 위 상수는 **카메라를 얹기 전** 값이다.
- **오른쪽 미수렴의 단독 원인** — 사람이 계속 오른쪽에 서 있어 준 관측이라, "기체가 못 돈
  것"과 "대상이 계속 옮겨간 것"을 데이터로 가르지 못했다. IMU yaw 로 직접 재려 했으나
  그 구간에 로봇 전원이 꺼져 무효였다. 육안 관찰이 근거의 전부다.
