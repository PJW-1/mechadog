## 1단계 — 모드가 「이름만」이 아닌가 (로봇 정지)

| 항목 | 결과 |
| :--- | :--- |
| `mode=guard` 표기 | 텔레메트리·사건·블랙박스 전부에 실린다 |
| 모르는 모드 기동 거부 | `--mode safety` 거부 (09-26 확인) |
| 화면 모드 상시 표시 | 하단 상태 칸과 장치 화면 양쪽에 `경비 모드` |
| `IDLE`·`MANUAL` 밖 전환 거부 | `FAILSAFE` 에서 「공장 모드」 요청 → **「거절됨 — FAILSAFE 에서는 모드를 바꾸지 않는다 — 멈춰 있을 때만 받는다」**. 요청 뒤에도 운용 모드는 `guard` 유지 |
| 경비 모드에서 PPE·구역 변화 사건 0건 | 사건 14건 전부 `person_found`·`escalation_changed`·`failsafe_entered`. PPE·`zone_changed` **0건** |

⚠️ **마지막 항목은 비전을 켠 상태에서 쟀다.** `vision_clients:1`, 사람을 추적 ID 64% 로 검출 중이었고
**보호구 미착용자가 화면에 있었다.** 09-24 에 `--no-vision` 으로 재서 0건이 나왔던 측정은
「모드 게이트가 막아서인지 카메라가 없어서인지 구분되지 않는다」는 이유로 무효였는데, 이번 측정이 그것을 대신한다.

## 2단계 — 사람 대응 사슬

### L1 → L2 승격 (`escalation.l1_to_l2_hold_s: 10`)

**5회 재현.**

| 회차 | L1 진입 | L2 진입 | 간격 |
| :--- | ---: | ---: | ---: |
| 1 | 07:09:09.910 | 07:09:19.920 | **10.010 s** |
| 2 | 07:14:21.763 | 07:14:31.763 | **10.000 s** |
| 3 | 07:15:20.915 | 07:15:30.918 | **10.003 s** |
| 4 | 07:43:15.427 | 07:43:25.509 | **10.082 s** |
| 5 | 07:45:40.217 | 07:45:50.219 | **10.002 s** |

L1 진입 사유는 모두 `person_present`, 상태는 `ALERT`(4회)·`TRACK` 경유. L2 사유는 `unauthenticated_hold`.

### 인증 무응답 → L3

```
07:45:50.219  auth_required / L2 / AUTH_WAIT
07:46:30.223  escalation_changed / L3 / ALERT  (AUTH_FAILED)
```

**40.004 s.** 설정과 맞춘다:

```
auth.auth_timeout_s 30  +  auth.auth_verdict_grace_s 10  =  40
실측 40.004 s (오차 4 ms)
```

⚠️ **`6.4.3` 검수표에 「30초」로 적어 둔 곳이 있다면 유예시간을 빼고 적은 값이다.** 실제 동작은 30+10 이다.

### 대상 이탈 → L3 (`escalation.target_lost_timeout_s: 5`)

`unauthenticated_left` 3회. L2 진입부터의 간격이 **30.294 / 17.952 / 39.697 s** 로 제각각이다 —
**시간이 아니라 실제로 사람이 사라진 시점에 반응한다.** 시간 기반이 아님을 보인다.

### 인증 통과 — `auth.require_both: true` 경로

```
07:15:30.918  auth_required        / L2 / AUTH_WAIT
07:15:42.377  voice_auth_granted   / L2 / AUTH_WAIT     ← 암구호
07:16:32.162  auth_granted         / L3 / PATROL        ← 사원증
```

**암구호 → 사원증 순서로 두 관문이 모두 통과했다.** `mechdog-02` 에서 처음이다.

- 암구호는 XIAO 마이크(`:82/audio`)로 들어온 발화를 PC 의 Whisper 가 인식한 것이다. 등록 문구 대조는
  공백·구두점을 지운 뒤 포함 관계로 본다 — 인식 결과의 띄어쓰기가 달라도 통과했다.
- 사원증은 `DICT_4X4_50` 마커를 **휴대폰 화면으로 제시**해 읽혔다. `3.8.1` 이 09-14 에 폰 제시로 판정된
  것과 같은 방식이며, 이번 카메라·회전(`rot=180`)에서도 읽힌다.
- ⚠️ **암구호는 `AUTH_WAIT` 에서만 판정된다.** 그 밖에서 문구를 정확히 말해도 인증 경로를 타지 않고
  일반 발화로 떨어진다. 인증을 재려면 먼저 L2 까지 올려야 한다.

### L3 해제 — 「경보 확인」으로만

`alarm_confirmed` 로 L3 → L0 **3회**. 그리고 안전 잠금과 경보가 서로 다른 관문임이 드러났다.

```
07:23:37.008  failsafe_cleared / L3 / IDLE  (failsafe_confirmed_alarm_kept)   ← F 만 풀리고 L3 가 남는다
07:23:42.402  escalation_changed / L0 / IDLE (alarm_confirmed)                ← 「경보 확인」을 따로 눌러야 해제
```

`ADR-26` 의 「L3 확인과 F 해제는 다른 버튼」을 실기로 확인한 것이다.

## 3단계 — 10분 무개입: 시도하지 못했다

두 가지가 막았다.

### ① 본체 링크가 주행 중 끊긴다

| 시각 | 상황 |
| :--- | :--- |
| 07:16:57.523 | `auth_granted` **25.4초** 뒤 `LINK_LOST` |
| 07:43:31.923 | L2 진입 **6.4초** 뒤 `LINK_LOST` |

- **정지 중에는 안정적이다** — 수신 10.0~10.3 Hz 를 하루 종일 유지했다.
- **주행 중에만** 7.7\~8.3 Hz·누락 5\~8건으로 떨어지다 끊겼다. 한때 1.3 Hz.
- 배터리는 7.94~8.31 V 로 여유가 있었으므로 **전압만의 문제로 보기 어렵다.**
- **로봇을 손에 들어 걷지 않게 하자 40초를 버텼다** — 위 `AUTH_FAILED` 측정이 그렇게 나왔다.

⚠️ 현장 관찰은 **배선이 보행 진동에 흔들려 접촉이 끊기는 것**을 원인 후보로 본다. 배선을 고정한 뒤
재측해야 갈린다. 전기·전파 문제로 단정하지 않는다.

### ② XIAO 가 반복해서 재부팅된다

하루에 **4회**. USB 직결로 급전을 바꾼 뒤에도 일어났으므로 전원 공급만의 문제가 아니다.
매번 카메라 회전이 `0` 으로 돌아가는 것으로 확인했다(현 펌웨어는 부팅 회전 0 으로 시작하고
`/orient` 는 재부팅까지만 유지되는 RAM 설정이다).

`6.4.3` 의 검수 항목이 **브라운아웃·리셋 0회**와 **10분 연속**을 요구하므로, 위 둘을 잡기 전에는
측정해도 결과를 쓸 수 없다.

## 한계

- **`L1 → L2` 를 뺀 시간 기준은 한 번씩만 쟀다.** 이탈(5초)·인증 유효(60초)는 재현 횟수가 부족하다.
- `3.5.3`(ALERT 자세)은 「고개를 든다」까지만 눈으로 봤고 **각도(`alert_pitch_deg: -15`)는 재지 않았다.**
- 쓰러짐 사건(`person_fallen`)이 경비 모드에서도 기록되는 것을 확인했다 — 모드 게이트는 단계 사유
  (`PERSON_DOWN` 등)를 막고 사건 이름은 막지 않는다. 다만 이번에 난 것은 **로봇을 손에 든 자세에서 나온
  것이라 `4.8.3` 판정 근거로 쓸 수 없다.**
- 카메라 회전은 매번 손으로 `/orient` 를 걸어 맞춘 상태에서 쟀다. 부팅 기본값은 이 측정 범위 밖이다.
