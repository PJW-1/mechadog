## V-0. 순정 펌웨어 백업 (OI-20) — ⚠️ **V-1 보다 먼저**

**V-1 은 커스텀 스케치를 업로드한다. 그 순간 출하 펌웨어는 사라지고 되돌릴 방법이 없다.**
출하 앱(모바일 앱 연동·데모 액션)을 다시 보여줄 수 없게 되므로, 시연 폴백과 A/B 비교 수단을 잃는다.

### 절차

```bash
python -m esptool --port COM? --baud 921600 read-flash 0 ALL stock_mechdog_<unit-id>.bin
```

```bash
certutil -hashfile stock_mechdog_<unit-id>.bin SHA256
```

**복원 확인** — 덤프를 뜬 **동일한 개체**에 다시 써서 출하 앱이 동작하는지 본다. 다른 개체의 덤프에는
개체별 설정이 포함될 수 있으므로 서로 바꿔 쓰지 않는다. **복원해 보지 않은 덤프는 백업이 아니다.**

```bash
python -m esptool --port COM? --baud 921600 write-flash 0 stock_mechdog_<unit-id>.bin
```

## V-1. 메인 ESP32 Wi-Fi 가용성 (OI-1 / RISK-01) — **최우선**

이 결과 하나로 **노드 간 배선이 필요한지 아닌지**가 갈린다. 가장 먼저 수행할 것.

### 절차

1. Arduino IDE에 ESP32 보드 패키지 설치 (Hiwonder 제공 `esp32_package_2.0.12_arduinome.exe` 또는 표준 보드 매니저)
2. 보드 타겟: **ESP32 Dev Module** / 업로드 속도 115200
3. `파일 → 예제 → WiFi → WiFiScan` 업로드
4. 시리얼 모니터 115200 baud로 결과 확인

```cpp
// 참고: 접속 확인까지 하려면 아래를 추가로 시험
WiFi.begin(SSID, PASS);
while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
Serial.println(WiFi.localIP());
Serial.println(WiFi.RSSI());
```

| STA 접속 성공 여부 | ⬜ 성공 / ⬜ 실패 |
| 할당 IP | ______ |

> **판정 기준** — RSSI가 **−70 dBm보다 양호**하면 정상 사용 가능. −80 dBm 이하이면 안테나 차폐를 의심하고 RISK-01 대응책(XIAO에서 UART 2가닥 중계)으로 전환.

**결론:** ⬜ Wi-Fi 직접 사용 / ⬜ UART 중계 필요

### 탑재 여력 부하 테스트

등에 추를 올린 상태로 **Trot 보행 3m 직진**을 시도하여 한계를 찾는다.

| 하중 | 보행 가능 | 자세 안정성 | 비고 |
| ---: | :---: | :--- | :--- |
| 30 g | ⬜ | | |
| 50 g | ⬜ | | |
| 80 g | ⬜ | | |
| **100 g** | ⬜ | | **Phase 2 필요 하중** |
| 130 g | ⬜ | | |

> **판정** — Phase 2 최종 구성(LD19 50g + 보조배터리 100~120g + MCU·케이블 25g + 마스트 20~40g ≈ **200~235g**)을 **마스트 높이에서** 이고 보행하면 진행.
> 약 600g 을 이고 걷는 것이 확인되었으나(RISK-02, 잠정) **측정 조건이 기록되지 않았다** — 마스트 높이·반방전·선회·10분 연속에서 재확인한다.
> 미달 시 Phase 2를 **ArUco 마커 기반 구역 정의**로 대체한다.

**결론:** ⬜ LiDAR SLAM 진행 / ⬜ ArUco 대체

> ⚠️ 무게 자체보다 **무게중심 높이**가 더 문제다. LiDAR는 마스트 위에 올라가므로, 추를 바닥이 아니라 **예상 마스트 높이에 올려놓고** 테스트할 것.

### 선회 성능 실측 (OI-22) — ⚠️ 이 값이 없으면 순찰 경로를 설계할 수 없다

`DR-11`(제자리 회전 불가) 때문에 로봇은 **자동차처럼 호를 그려서만** 방향을 바꾼다.
`FR-6.5`·`FR-7.5` 가 *"경로는 최소 회전 반경을 존중해야 한다"* 고 요구하는데 **그 값이 없다.**

**측정법** — 최대 조향각으로 계속 선회시켜 **바닥에 원을 한 바퀴 그리게** 하고 그 지름을 잰다.

| 하중 | 조향각 | 최소 회전 반경 | 한 바퀴 소요 | 비고 |
| ---: | ---: | :--- | :--- | :--- |
| 무부하 | 30° (최대) | ______ mm | ______ 초 | |
| 무부하 | 20° (`config` 기본값) | ______ mm | ______ 초 | |
| **200~235 g** (마스트 높이) | 30° | ______ mm | ______ 초 | **Phase 2 구성** |

| 항목 | 측정값 | 왜 재나 |
| :--- | :--- | :--- |
| 후진 200mm + 선회로 벗어날 수 있는 **최소 통로 폭** | ______ mm | `AVOID` 회피 시퀀스(FR-2.3)가 성립하는 폭 |
| 좌우 선회 반경 차이 | ______ mm | 개체 편차·서보 오프셋 영향 (2.4.1) |

> **판정 기준** — 시연은 **방 하나**에서 하고 구역은 **A·B·C 3개**다.
> **회전 지름이 방의 짧은 변에 가까우면 구역 간 이동이 성립하지 않는다.**

| 조건 | 조치 |
| :--- | :--- |
| 회전 지름 ≤ 방 짧은 변의 1/3 | 구역 순찰 설계 진행 |
| 그 이상 | **구역 수 축소** 또는 **구역을 회전 없이 직선 왕복으로 배치**. Phase 2 범위 재조정 |

**결론:** 최소 회전 반경 ______ mm · ⬜ 구역 순찰 성립 / ⬜ 배치 재설계 필요

## V-9. LiDAR 시야 확보 및 2대 상호 간섭 — ⚠️ **LiDAR 도착 후** `[P2]`

> **이 항목만 M0 가 아니다.** 장비가 없으면 수행할 수 없으므로 `2.5`(하드웨어 검증 리포트)의
> 완료 기준도 **V-0~V-8** 까지다. LiDAR 가 도착한 뒤에 채운다.

**LiDAR 는 3대 중 2대에 장착한다.** 그래서 확인할 것이 두 가지다.

### ① 자기 차폐 — 로봇 자신이 스캔을 가린다

LD19 는 360° 를 돈다. 마스트 위에 올려도 **몸통·배터리·마스트 자체가 일부 방위를 가린다.**
가려진 각도를 모르면 SLAM 이 그 방향의 벽을 "없는 것" 으로 학습한다.

| 항목 | 결과 |
| :--- | :--- |
| 유효 스캔 방위 | ______° ~ ______° (차폐 구간: ______) |
| 전방 180° 내 차폐 유무 | ⬜ 없음 / ⬜ 있음 → 각도: ______ |
| 최소 유효 거리 (자기 구조물 반사) | ______ m |
| 대응 | ⬜ 불필요 / ⬜ `angle_min/max` 마스킹 / ⬜ 마스트 높이 상향 |

### ② 2대 동시 가동 시 상호 간섭

두 로봇이 같은 공간에 있으면 **한쪽 레이저가 다른 쪽 수신부에 들어가 유령 점(phantom return)** 이
생길 수 있다. 협동 시나리오(OI-21)를 정하기 전에 알아야 한다.

**측정 방법** — 같은 장소·같은 필터 설정에서 ① LiDAR 1대만 60초 ② LiDAR 2대를 동시에 60초씩
측정한다. 아래 세 배치를 각각 **3회 반복**하고, 단독 기준선 대비 무효/이상 거리점 비율과 지도 흔들림을
기록한다. 허용치는 시험 전에 빈칸에 적어 판정 기준을 사후 변경하지 않는다.
