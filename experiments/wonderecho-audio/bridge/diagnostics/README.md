# WonderEcho v35 — 무음 원인 분리를 위한 상태 출력

**빌드·공식 패키징 검증 완료, 기기 미설치·실물 미검증. 무음 해결본이 아니다.**

- 설치 파일: `<OUT_DIR>/35-diag.bin`
- 버전: 2.1.35 / build3501
- SHA256: `ac3dbe1b54f3b287e04c9ea61edb012fb8ba1b266595f80eb6549c78274d930f`
- user code: 151,160 B. 전체 이미지: 1,969,737 B.
- UART0: 921600bps 로그 전용. WEC1·PC 녹음·PC TTS 스트리밍은 비활성.
- UART1: v34와 같은 115200bps 공장 브리지. 지원 ID·프로토콜·핀·코덱·음량 상한40·모델·리소스는 그대로다.

## 필요한 이유

v34에서 외부 I²C 0x34의 ACK는 확인했으나 실제 소리·반응은 없었다. USB에서는 `we_bridge` 태스크만 주기적으로 확인됐다. 수신 중 RST를 눌렀다는 사용자 보고도 있었지만 부팅/초기화 로그를 얻지 못해 실제 재부팅 여부는 미확정이다.

v34는 초기화 결과를 한 번만 출력하고, 플레이어가 사용 중일 때 방송을 로그 없이 거절한다. 따라서 로그가 없다는 사실만으로 UART 미수신과 플레이어 거절을 구분할 수 없다. v35는 이 관측 공백만 보완한다.

## 변경·검증

SDK 사본 `<WE_SDK_TREE_DIAG>`에서 main.c, user_msg_deal.c, we_bridge.c, we_bridge.h 네 파일만 달라짐을 파일 해시로 확인했다. 기존 10초 모니터에 여섯 줄의 짧은 소프트웨어 상태 출력을 추가한다. 별도 태스크·타이머·수신 명령을 만들지 않는다. ISR은 수신 바이트 카운터만 추가하고 로그를 출력하지 않는다.

CI1302 GCC 컴파일·링크, 브리지 파일 `-Wall -Wextra -Werror`, code0+libfbin 공식 merge와 공장 부트/ASR/DNN/voice/user/NV 배치 보존 검사를 통과했다. SDK 기존 경고는 남아 있다. 프로토콜 파일과 v34 SDK/BIN, v27/latest 해시가 유지됨을 확인했다. 실물 실행 시 로그 부하·실제 수신·발화는 미검증이다.

RAM 소프트웨어 값만 읽으며 codec/GPIO/미문서화 레지스터 조회나 복구 동작은 없다. 각 값은 독립적인 순간 관찰이며 한 시점의 원자적 스냅샷은 아니다. callback 증가도 실제 소리를 증명하지 않는다.

## 로그 해석

| 필드 | 의미 |
| --- | --- |
| build, tick | 후보 식별값 및 RTOS tick. tick의 감소만으로 재부팅을 단정하지 않는다. |
| phase, init, ready | phase0 미호출, 1 매핑검사, 2 큐/태스크, 3 UART 초기화, 4 완료. init100 미완료, 0 성공, 음수 실패. |
| bytes, frames, uart_err | UART1 ISR에서 읽은 바이트, 파서가 인정한 프레임, UART 오류. bytes0은 해당 ISR의 미관측이며 전기적 파형 부재를 증명하지 않는다. |
| tx | FIFO에 프레임을 쓴 횟수. 외부 브리지의 수신 ACK가 아니다. |
| drop, expired, unknown, busy | 큐/TX/만료 폐기 합계, 만료 횟수, 미지원 ID, 플레이어 사용 중 거절. expired는 drop에도 포함되며 합산하지 않는다. |
| accept, callbacks, failed | SDK 재생 요청 수락, 완료 콜백, 거절/실패. busy는 failed에도 포함된다. |
| player, prompt, mute, wake | SDK 플레이어 상태값, 프롬프트 작업 존재, 마이크 음소거 플래그, 깨우기 상태값. mute1 하나만으로 오류 판정하지 않는다. |
| asr_seen, last_asr | sys_asr_result_hook 호출 횟수와 마지막 내부 명령 ID. 마이크 파형/모든 인식 후보 계수는 아니다. |

## 다음 실물 단계

1. 모듈 4핀을 분리한 USB 단독 상태에서 위 파일을 기존 PACK_UPDATE_TOOL 절차로 설치하고 업데이트 도구를 닫는다. 포트 번호는 연결 때 재확인한다.
2. COM5였던 모듈의 UART0@921600을 수신한다. 부팅 순간을 놓쳐도 `[WE-STAT] build=3501 phase=4 init=0 ready=1`을 확인할 수 있다. 이 출력은 음성 재생 성공 판정이 아니다.
3. USB 단독 깨우기/인사 입력 전후의 mute·prompt·ASR·callback 상태와 실제 소리를 대조한다.
4. 초기화가 확인되면 모듈 USB를 제거하고 전원을 분리한 상태에서 로봇 4핀을 연결해 다음 시험을 설계한다. USB와 4핀의 동시 5V 급전은 하지 않는다. 로봇 SERVICE/SAFE 상태를 재확인한다.

현재 이 후보는 설치되지 않았다. 기기 로그에3501이 나오기 전까지 설치된 것으로 간주하지 않는다. 구동·OTA·모델 변경·기존 이미지 교체·Git 게시 없음.
