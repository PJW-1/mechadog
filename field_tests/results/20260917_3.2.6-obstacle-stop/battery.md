# WBS 3.2.2 실측 — 저전압 감시 (2026-09-17 · mechdog-01)

## 가변전원 없이 교차를 만든 방법

`3.2.2` 의 완료 기준은 **7.0V·6.6V 교차 시 플래그 전환과 셧다운 동작 확인**이다. 가변전원이 없고
실제로 6.6V 까지 방전시키는 것은 30~60분이 걸리며 팩에도 좋지 않다.

**대신 보행 부하가 만드는 전압 강하를 썼다.** 같은 날 측정에서 정지 8.320V 가 공중 보행 중
**8.04V** 까지 내려앉았다(강하 약 0.28V). 그래서 시험 빌드의 임계를 **경고 8.12V · 셧다운 8.05V**
로 두면, **걷기 시작하는 순간 셧다운선을 아래로 지나간다.** 방전을 기다리지 않는다.

    -DMECHADOG_BENCH_BATTERY_THRESHOLDS=1
    -DMECHADOG_BENCH_BATTERY_WARN_V=8.12f -DMECHADOG_BENCH_BATTERY_SHUTDOWN_V=8.05f

⚠️ **판정 코드는 정식 빌드와 같은 경로다.** 바뀌는 것은 비교할 숫자뿐이다.

## 결과 — 7/7 통과

| 확인 | 결과 |
| :--- | :--- |
| 정지 상태(8.132V)에서 래치 없음 | 해제 뒤 `latched=false` 유지 |
| 보행 시작 → 경고 | **`flags.lowbatt=true`** (8.080V) |
| 보행 시작 → 셧다운 | **2초 안에 SAFE 래치** |
| 상태 보고 | `state=FAILSAFE` |
| 래치 중 전진 | **`applied=false`** — 거부 |
| 자동 복귀 | 없음 — 기다려도 풀리지 않는다 |
| UART 기록 | `Battery shutdown: 8.04V <= 8.05V` |

**걷기 시작 2초 만에 걸렸다.** 부하 강하가 셧다운선을 지나간 것이고, 연속 3표본 요구가 있어
그 사이의 흔들림 한두 번으로는 걸리지 않는다.

## 이 시험이 잡은 것 — 로그가 거짓말을 하고 있었다

처음 기록은 `Battery shutdown: 8.04V <= 6.60V` 였다. 실제로 쓰인 임계는 8.05V 인데 **정식 상수
6.60V 를 찍고 있었다.** 벤치 빌드가 아니었다면 영원히 드러나지 않았을 것이고, 나중에 누가 이
줄을 근거로 *"6.6V 에서 걸렸다"* 고 읽었을 것이다. `SafetyMonitor::thresholds()` 를 열어
**실제 사용 임계**를 찍도록 고쳤다.

## 정식 임계에서의 확인

시험 뒤 정식 빌드(7.0V / 6.6V)를 다시 올려 확인했다 — 8.088V 에서 `lowbatt=false`, 전진
`applied=true`, 래치 없음. **시험용 임계가 기체에 남아 있지 않다.**

## 남은 것

- ⚠️ **전압 읽기는 여전히 보정 전이다**(`battery_calibrated=false`). 6.6V 라고 적힌 선이 실제
  몇 V 인지는 멀티미터 대조가 필요하다. 이번 시험이 확인한 것은 **교차 시 동작**이지 값의
  정확도가 아니다.
- **벤더 경고음은 7.0V 다** — `Hiwonder.cpp` 의 `PowerBuzzer::readBattery` 가
  `analogRead(34) * 3.6 < 7000` 에서 부저를 울린다. 팀장이 실사용에서 여러 번 들은 그 소리이며,
  우리 `NFR-2.3` 경고 임계와 우연히 같은 값이다. ⚠️ **부저는 벤더 태스크가 독립적으로 울린다** —
  우리 감시기의 래치 동작과는 무관하므로, 그 소리를 래치의 근거로 삼을 수 없다. 이번 시험이
  래치 쪽을 따로 확인한 이유다.
- 실제 6.6V 구간의 거동(그 아래 6.0V 에서 텔레메트리 발행이 막히는 것과의 상호작용)은
  배터리 지속시간 측정(`2.2.2`)에서 자연히 지나가므로 그때 함께 본다.
