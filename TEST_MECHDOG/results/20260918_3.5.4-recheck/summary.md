## 1단계 — #199 상태(좌우 공통 보정): 오른쪽은 살고 왼쪽이 죽었다

원자료 `track_commands.txt` · `track_summary_1hz.txt` · `track_events.txt`.

| | 직전 런 (보정 전) | 1단계 (좌우 공통 보정) |
| :--- | :--- | :--- |

| **왼쪽** | 183 → 11px · 12초 | ❌ **−112.6px 에서 조향 효과 0 · 미수렴** |

오른쪽은 의도대로 살아났다. `track_angle_deg_avg` 가 편차를 따라 **19.8° → 8.4°** 로 줄어
비례 제어가 전 구간 동작했다(직전 런은 7~13.8°가 계속 나가는데도 편차가 줄지 않았다).

그런데 같은 보정이 왼쪽을 없앴다.

```
dev -112.6px  →  raw +5.19°(좌) + (-8.0) = -2.81°  →  |2.81| < 3.3(우 데드밴드)  →  조향 0
dev -125.8px  →  raw +6.13°(좌) + (-8.0) = -1.87°  →  조향 0
```

왼쪽이 실제로 꺾이려면 `raw − 8 > 3.3` 이라 **편차가 198px 을 넘어야 했다.** 데드존을 40px
로 정해 놓고 **한쪽만 조용히 5배로 키운 셈**이다. 드리프트가 좌라면 그것을 갚아야 하는 것은
**우선회뿐**이고, 좌선회는 드리프트가 같은 방향이라 이미 덤을 받고 있다.

## 2단계 — 함께 드러난 결함: `ALERT` 에 33초 갇힘

  기동 로그의 `actions={PATROL, ZONE_INSPECT, TRACK, AVOID}` 에 `ALERT` 가 빠져 있는 것이 그것이다.
- `TRACK` 으로 넘어갔어야 하는데 못 넘어갔다. `runtime._track` 이 `centered` **변화가 있을
  때만** 사건을 내는데, 직전에 `MANUAL` 로 추종을 빠져나오며 `centered=False` 가 남아 있었다.
  다시 들어왔을 때도 `False` 라 **변화가 없어 `TARGET_OFF_CENTER` 를 삼켰다.**

상태를 나갔다 들어와도 엣지 기억이 지워지지 않는 것이 원인이다. 실기가 아니면 드러나지 않았을

## 함께 드러난 것 둘

**① `ALERT ⇄ TRACK` 플래핑** — 1단계 02:08:59 에 **한 초 안에 3왕복**했다
(`35.4 → 41.2 → 37.2 → 44.3 → 3.3px`). 데드존 경계에서 bbox 가 **±5px** 떨리는 것이 그대로
전이가 된다. 히스테리시스가 없어서이며, `tracker.py` 가 *"간격을 정하려면 bbox 가 얼마나
떨리는지를 재야 한다"* 고 적어둔 그 값이 이번에 측정됐다. **해제 임계를 40 → 50px 로 벌리는
것이 후속이다.**

**② 전원이 꺼지면 `LINK_LOST` 가 정확히 그대로 보인다** — 02:30:17 에 텔레메트리가 통째로
끊기고(`accepted` 10 → 2 → 없음) 호스트가 3초 뒤 `LINK_LOST` 로 래치했다. **운용자가 시험을
마치고 로봇을 끈 것이며 결함이 아니다.** 직전 런의 00:53:00 도 같다 — **09-18 의 로봇 종료는
전부 운용자 조작이고 예상치 못한 종료는 0건이다**(2026-09-18 운용자 확인). 그동안 호스트는
10/s 를 계속 보내고 있었다.

⚠️ **이 모양을 배터리 탓으로 읽지 않는다.** 처음에는 그때 `batt_v` 가 7.75~7.78V 였다는 것만
보고 브라운아웃으로 적었다가 운용자 확인으로 정정했다. **전원 차단과 저전압 강제종료는
로그에서 구분되지 않는다** — 둘 다 "텔레메트리가 갑자기 없어진다" 로 똑같이 보인다.
구분하려면 전압 추이(급락인지 평탄인지)를 따로 봐야 하고, 이번 두 건은 평탄했다.

## 직전 런 기록의 정정 — 명령 링크는 나빠지지 않았다

직전 summary 의 *"② 명령 링크 여유가 줄었다(`last_cmd_age_ms` 13.1 → 88.5ms)"* 는 **오독이다.**
이 값은 로봇이 텔레메트리를 낼 때 찍는 `now − g_last_valid_command_ms` 이므로, 서로 독립인
두 10Hz 루프의 **위상차**이며 0~100ms 안에서 아무 값이나 된다. 호스트를 재시작할 때마다 새로
뽑힌다 — 09-18 여섯 세션의 중앙값이 12.9 / 73.0 / 81.8 / 53.9 / 67 / 29ms 였다.

같은 근거로 *"최대 3,575ms"* 는 기동 첫 초의 값이다 — 호스트가 붙기 전에 로봇이 마지막으로
받은 명령의 나이이며, 같은 자리에 441,625ms(7.4분)짜리도 있다. 그리고 직전 런의 `LINK_LOST`
는 **로봇 전원이 꺼져서 생긴 것**이다(위 ② 참조). 세 가지 모두 전파 경합의 흔적이 아니다.

## 미확정으로 남긴 것

- **좌 데드밴드는 여전히 미측정이다.** 위 86px 은 우 데드밴드(3.3°)를 빌린 계산이고, 이번
  실기의 평탄 구간(75~88px)이 그것과 겹친다는 것까지가 확인된 전부다.
- **각속도(°/s)로 재지 않았다.** `telemetry_summary` 에 IMU yaw 가 실리지 않아 px/s 로만
  비교했다. px/s 는 거리에 종속돼 같은 런 안에서도 2배씩 달라진다 — 좌우를 숫자로 못 박으려면
  요약에 yaw 한 칸이 필요하다.
- **바닥·배터리 변경 시 재측정.** 개루프 보정의 한계다. 측위(`3.9.x`)나 IMU 요 폐루프가 서면 없어진다.
