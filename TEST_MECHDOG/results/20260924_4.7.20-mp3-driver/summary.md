# 4.7.20 로봇 MP3 모듈 드라이버 — 실기 (2026-09-24 · `mechdog-01`)

MP3 모듈(IIC1 `0x7B`)에 공장 TF 카드(`/MP3/0016街舞.mp3` ~ `0024爱出发.mp3` 9곡)를 꽂고,
로봇 펌웨어 경로(`tools/mechdog_command.py <IP> sound N`)와 진단 스케치(`i2c_bridge_probe`)로 확인했다.
로봇은 처음부터 끝까지 FAILSAFE 래치 상태였다(`safe_latched=true`). 소리는 사람이 귀로 판정했다.

판정: **통과.** 래치 중 `SOUND 17` 재생 · `SOUND 0` 정지 · `SOUND 3001` 거부.

## 확정한 모듈 동작

| 확인 | 결과 |
| :--- | :--- |
| `0x01 ← 11 00` (2바이트 LE) 만 씀 | `0017江南Style` 재생 — **트랙 쓰기 하나가 재생 시작**이고 번호는 **파일 이름 앞 네 자리**다 |
| `0x01 ← 02 00` (카드에 없는 번호) | 무음. 1.5초 뒤 `0x01 ← 17` 은 정상 재생 — 없는 번호가 모듈을 막지 않는다 |
| `0x05` | 재생 (모듈 전원 직후 첫 곡) |
| `0x06` | 멈춘다 |
| 재생 **전**에 `0x0C ← 10` → 트랙 | 음량이 **버려져** 최대 크기로 나왔다 |
| 재생 **중**에 `0x0C ← 10` / `← 3` | 반영됐다 |
| 트랙 → **20ms** → `0x0C ← 15` | 중간 크기로 반영됐다 |
| 음량 → 20ms → 트랙 | 재생됐다 (간격 20ms 는 문제가 아니다) |
| `0x7E` | 확인 못 함 |

그래서 펌웨어 순서를 **트랙 → 20ms → 음량** 으로 바꾸고 기본 음량을 25 → **15** 로 내렸다(사용자 지정).
정지(`0`)는 음량을 쓰지 않는다.

## 첫 빌드(음량 → 트랙 순서)가 무음이었던 경위

첫 빌드(`2026-09-24_mp3-driver`)로 보낸 `SOUND` 는 전부 무음이었다. 조건을 가려 보면:

- 01:36~01:45 — TF 카드가 PC 리더기에 있던 시간으로 본다. 판정에서 뺀다.
- 01:49~01:52 — 모듈을 **다른 4핀 포트**로 옮겼다. I²C 무응답(`SOUND dropped: MP3 module not answering`)이었고,
  그동안 배터리 ADC 가 **`battery_raw=4095` 에 붙었다**(뺀 01:51:49~01:52:03 에는 8.58 V 로 정상). 그 포트는
  배터리 측정 핀(GPIO34)과 이어져 있다 — **MP3 모듈은 IIC1 포트에만 꽂는다.**
- 01:53:10 `SOUND 2`(카드에 없음), 01:53:55 `SOUND 17` — 올바른 포트·카드 장착 상태에서 무음.
  진단 스케치로 같은 바이트·같은 20ms 간격을 재현하자 재생됐으므로, 이 한 번의 무음은 **원인을 가리지 못했다.**
  고친 빌드로는 재생 3/3 · 정지 2/2 였다.

## 부수 수정

- `tools/mechdog_command.py sound` 가 `seq=1 STOP` 없이 시작해, 두 번째 실행부터 펌웨어가 `seq 역전·중복` 으로
  조용히 버렸다(ACK 없음). 다른 하위 명령처럼 `STOP` 을 먼저 보내게 고쳤다. `STOP` 은 래치를 풀지 않는다.
