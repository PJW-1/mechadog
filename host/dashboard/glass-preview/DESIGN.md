# MechaDog 흰색 관제 화면

2026-09-29 디자인 기준 · 2026-09-30 Git 통합. 기존 흰색 화면의 레이아웃과 모션을 정리했다.

## 화면 목적

Operate: 로봇과 영상의 실제 연결 상태를 파악하고, 사건·장치·제어 작업으로 이동한다. 예시 데이터와 실물 데이터를 구별하는 기존 문구와 동작을 유지한다. 기본 화면은 glass-preview이며 과거 검정 웹을 기본으로 재실행하지 않는다.

## 시각 규칙

- 흰색 작업면, 연한 회색 바탕, 짙은 녹색 선택/주요 버튼. 노랑은 참고·주의, 빨강은 실제 위험/정지 의미에만 사용한다.
- Noto Sans KR 기존 글꼴 유지. 페이지 제목 28px, 본문 13–14px, 보조 상태 11–12px. 주요 입력/조작은 작은 화면에서 충분한 크기로 유지한다.
- 900px 이상은 폭 176px(좁은 데스크톱 156px)의 고정 메뉴. hover/focus에 따라 본문 폭을 바꾸지 않는다. 작은 화면은 상단 메뉴와 세로 콘텐츠 흐름.
- 구역 간 24–36px, 묶음 내부 8–16px. 작업면은 1px 테두리, 반경 7–12px. 그림자는 카메라 창/팝업/대화상자의 겹침 표현에만 쓴다.
- 카메라는 드래그·크기 조절·확대·접기의 기존 동작을 유지한다. 휴대폰은 지도 아래 흐름에 놓는다. 사건 목록과 상세는 넓은 화면에서 두 열, 휴대폰은 한 열.

## 모션 규칙

- 화면 전환 240ms, 카메라 창 FLIP 280ms, 3D 시점 220–380ms. 클릭 처리는 즉시 완료하고 시각적 연결만 애니메이션으로 표현한다.
- telemetry/frame 갱신이나 같은 페이지의 목록 재작성마다 입장 효과를 재실행하지 않는다.
- 새 3D 조작은 현재 시점에서 다시 시작한다. 직접 드래그하거나 화면을 나가면 시점 전환을 해제한다. reduce-motion은 즉시 도착/공간 이동 제거, 색상 피드백 유지.
- 상시 배경 이동·그림자 맥동·포인터 추적 장식 없음. 렌더링은 기존 demand-render 흐름과 유한한 시점 전환을 사용한다. 성능 향상 수치는 계측하지 않았다.
- WebGL 크기는 변환 중의 시각적 bounding box가 아니라 canvas clientWidth/clientHeight로 계산한다.

## 범위와 검증

관제 웹의 8개 화면과 320–1440px 화면 폭을 대상으로 한다. 실제 로봇/센서 구동과 AI 모델 변경은 이 디자인 범위에 포함하지 않는다. 화면에 표시하는 로봇 슬롯은 최신 관제 코드의 MD-01·MD-02 두 대와 일치시킨다. 자동시험 및 정적 검사는 통합 브랜치에서 다시 실행한다.

## Colors

기존 흰색 바탕과 녹색 조작을 계승한다. 색상만으로 저장 또는 연결 상태를 전달하지 않는다.

### Primary

기존 주요 버튼은 짙은 녹색 배경과 흰 글자, hover는 더 짙은 녹색이다. 순서 목록은 옅은 녹색 채움과 녹색 계열 테두리로 선택을 표시하고 `aria-pressed`를 함께 제공한다.

### Neutral

기존 바탕 `--bg` (#f4f5f2), 작업면 `--panel` (#fff), 본문 `--ink` (#25352e), 보조 `--muted` (#596b61)을 잇는다. 확장의 반복 구분선 (#dce3db)은 세 영역의 경계에 쓰인다. 지도 부재 작업면은 옅은 회녹색이며 지도 데이터로 오인시키는 가짜 현장 이미지는 없다.

**The Explicit State Rule.** 녹색/호박색 보조 표현에는 작성·저장·적용 상태 문구를 함께 둔다. 위험물 점검 반경과 경로 없음의 호박색을 일반 선택색으로 사용하지 않는다.

## Typography

**Body Font:** 기존 `Noto Sans KR`, `Malgun Gothic`, sans-serif. 새로운 표시용 글꼴은 추가하지 않았다.

### Hierarchy

- 기존 페이지 제목 28px, 작은 화면 25px 아래에 확장 작업 제목 23px/650, 899px 이하 21px를 둔다. 이 작업 제목은 해당 화면의 구성값이며 전역 display 토큰으로 확대하지 않는다.
- 반복 구역 제목 14px/650, 목록 이름·설명 본문 13px, 상태·조작 12px, 보조 정보 11px의 조밀한 계층이다.
- 설명은 대체로 1.6–1.8 줄높이, 순서·구간 수치는 tabular-nums를 사용한다. 550px 이하 입력 글자는 기존 테마의 16px 규칙을 따른다.

**The Editable Precision Rule.** 좌표 요약은 소수 두 자리지만 편집 값은 유효한 0.001m 단위를 유지한다. 요약 반올림을 저장 정밀도로 사용하지 않는다.

## Layout

**The Ordered Workspace Rule.** DOM과 좁은 화면 흐름은 순서 목록 → 지도 → 구역 설정이다. 1190px 초과에서는 `minmax(180px,.85fr) minmax(300px,2.4fr) minmax(235px,1fr)`의 세 열이다. 900–1190px에서는 190px 목록과 `minmax(260px,1fr)` 지도 아래에 설정 영역이 전체 폭으로 내려가며 설정 내부는 두 열이다. 899px 이하에서는 세 영역이 한 열로 쌓인다. 두 열 중간 구간은 CSS 근거이며 제공 캡처에는 없다.

반복 내부 간격은 8–16px, 주요 묶음/행동부 간격은 24px다. 목록·설정 내부 여백은 20px 16px, 지도는 20px에서 좁은 화면 16px로 바뀐다. 상단 상태와 저장/다시 불러오기는 줄바꿈하며 899px 이하 상태는 왼쪽 정렬이다. 바깥 작업면 여백은 기존 테마에서 상속되므로 이 확장을 무조건 무여백이라고 규정하지 않는다.

899px 이하 일반 계획 버튼은 최소 40px, 숫자 입력·메모는 최소 44px다. 550px 이하에서는 기존 테마의 더 높은 선택자 우선순위로 작업 버튼 최소 44px가 적용된다. 이 차이를 모두 같은 터치 크기로 기록하지 않는다.

## Elevation & Depth

이번 확장은 흰색/옅은 면과 1px 경계로 깊이를 구분한다. 새 그림자·유리 효과·공간 이동 애니메이션을 도입하지 않는다. 기존 카메라·팝업·대화상자 깊이 규칙을 그대로 보존한다. 목록 선택과 hover는 배경/테두리 160ms 변화이며 기존 reduced-motion 규칙은 버튼 색상 피드백을 100ms로 줄이고 공간 이동을 제거한다. 정적 캡처가 reduced-motion 동작 시험을 대신하지 않는다.

## Shapes

기존 둥근 조작부(7px)와 1px 테두리를 재사용한다. 합쳐진 계획 작업면은 10px, 지도 작업면은 6px 반경을 사용한다. 이 두 구성값을 새 전역 반경 체계로 승격하지 않는다. 빈 지도 안의 CSS 격자 표시는 데이터 없는 상태의 안내 그림이며 실제 지도나 센서 래스터가 아니다.

## Components

### Buttons

주요 저장과 보조 다시 불러오기/경로 확인은 기존 버튼을 재사용한다. 저장은 서버 저장본·수정 사항이 있고 로딩/처리/숫자 오류가 없을 때 활성화한다. 지도 부재에서는 경로 확인이 비활성이다. 비활성에는 커서와 투명도, 상태 문구를 함께 제공한다.

### Itinerary

선택·위/아래 순서 변경은 실제 버튼이다. 목록을 다시 그릴 때 현재 구역/순서 버튼을 찾아 초점을 복원하고 이동 불가한 끝에서는 선택 버튼으로 돌아간다. 새 구역 추가는 이름 입력에 초점을 둔다. 순서와 선택을 색상만으로 전달하지 않는다.

### Map and route

지도는 서버의 저장 지도 이미지와 extent를 사용하고 SVG로 구역·반경·방향·도달 가능한 경로를 겹친다. 지도 부재 시 안내를 표시한다. 경로 결과는 계산된 저장 지도 결과이며 실물 주행 검증이나 출발 명령이 아니다. 좌표 입력이 지도 클릭의 키보드 대안이다. SVG 점 자체를 키보드 버튼이라고 주장하지 않는다.

### Inspector and state

좌표 입력 step은 0.001, X/Y 범위는 ±10000m다. 지도 클릭은 소수 세 자리로 저장한다. 유효하지 않은 숫자는 `aria-invalid`로 표시하고 저장·경로 확인을 막는다. 이름·좌표·방향·보호구·위험물·메모를 선택 구역에서 편집한다. 좌표 지우기는 짝 좌표와 방향도 비운다.

초안은 연결 대상/로봇별로 분리한다. 저장된 설정과 active 설정을 구분하고 재시작 후 적용 상태를 명시한다. 서버 저장본으로 초안을 교체할 때 확인이 있으며 저장 실패 시 작성 내용을 유지한다. 저장/불러오기/계산 중 입력을 잠근다. 계획 저장은 로봇 이동 시작이 아니다.

### Keyboard and motion

확장 focus-visible는 녹색 2px 외곽선과 3px 간격을 선언한다. 실제 숫자 입력·메모에는 기존 `#panel-content` 초점 선택자가 더 높은 우선순위를 가져 기존 금색 외곽선이 남는다. 따라서 모든 초점이 녹색이라는 규칙은 기록하지 않는다. 키보드 상태의 실제 가시성·대비는 제공 캡처에서 확인되지 않았다. 기존 테마의 reduced-motion 처리를 계승하며 별도 반복 모션은 추가하지 않는다.

## Do's and Don'ts

### Do:

- **Do** 기존 흰색·녹색 정체성과 순서/지도/설정의 흐름을 유지한다.
- **Do** 초안·저장본·운용 적용 상태와 실제 지도 부재를 명시한다.
- **Do** 편집 정밀도·키보드 초점 연속성·기존 reduced-motion 동작을 유지한다.

### Don't:

- **Don't** 저장이나 지도 경로 계산을 실물 운용 적용·주행 검증으로 표시한다.
- **Don't** 실제 지도 대신 예시 공장이나 장식 래스터를 넣는다. 새 shipping raster asset은 없으며 리뷰 캡처는 배포 자산이 아니다. 런타임 지도 PNG는 센서 지도 데이터다.
- **Don't** 캡처되지 않은 상태, 인계받은 시험, 시드 프로토콜 충돌을 전체 UI 승인으로 바꿔 적는다.

Not canonized: 기존 작은 10px 메타데이터·op-eyebrow 스타일 및 입력 초점색의 레거시 불일치는 개선 검토 대상으로 남긴다. 새 화면에 물려줄 규칙으로 정당화하지 않는다. 제공 이미지의 흐림이나 제한된 캡처 범위도 디자인 규칙이 아니다.
