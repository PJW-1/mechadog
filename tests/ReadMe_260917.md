## 끝나면 엑셀에 이렇게 채운다

각 항목의 **엑셀 WBS** 번호를 `일정과 업무` 시트 A열에서 찾아 그 행에 기입한다.
**하위 항목이 전부 끝나야 그 행이 완료다** — 시트는 2단계(`2.1`), 작업은 3단계(`2.1.3`)이기 때문이다.

| 열 | 채울 것 |
| :--- | :--- |
| I · 상태 | `완료` |
| J · 실제완료일 | 실제 측정한 날 |
| K · 결과·검증 요약 | 측정 수치 (합·불이 아니라 **숫자**) |
| L · 근거 링크 | 리포트 경로 또는 PR 번호 |
| M · 확인자 | 본인 |

> 이 다섯 칸이 전부 차야 P열 자동판정이 `검증완료`가 된다. 하나라도 비면 `자료 필요`로 남아 집계에 안 잡힌다.

# ① `2.1.3` 센서 기본 동작 확인 → 엑셀 `2.1`

## A. 초음파

1. **장치 설정** — 초음파 센서(I2C `0x77`) 배선을 확인하고 로봇을 Wi-Fi 에 올린다. 서보는 비활성 빌드 그대로 둔다.
2. **코드 추가** — 펌웨어에 초음파 읽기를 넣어 텔레메트리 `dist_cm` 을 채운다(측정 불가는 **0 으로** 남긴다). 호스트는 `TEST_MECHDOG/checks.py` 에 `check_ultrasonic_read()` 를 만들고 `run_tests.py` 에서 부른다.
3. **정리 파일 생성** — `python TEST_MECHDOG/run_tests.py` 를 돌려 `results/<날짜>/report.md` · `report.json` 을 받고, 거리 3지점 수치는 같은 폴더에 `sensor_2_1_3.md` 로 적는다.
4. **결과 기록** — 10cm · 30cm · 50cm 의 실측값과 오차, 텔레메트리 반영 주기.
   → **초음파가 실제로 살아 있고 그 값이 무선으로 올라오는가**

## B. IMU

칩은 **QMI8658(`0x6A`)** 으로 확정됐고, I2C 직접 읽기로 중력 0.99g 까지 확인됐다.
남은 것은 **그 값을 얼마나 믿을 수 있는지 재는 일**이다.

1. **장치 설정** — 로봇을 **수평이 확인된 바닥**에 놓는다. 기울기 기준으로 쓸 각도기(또는 15° · 30° 경사 지그)를 준비한다. **벤더 예제가 부르는 `0x68` 은 이 보드에 없다.**
2. **코드 추가** — `firmware_mechdog_motion/diagnostics/imu_probe/imu_probe.ino` 의 I2C 직접 읽기를 본 펌웨어로 옮겨 텔레메트리 `imu.pitch` · `imu.roll` 을 채운다(**`yaw` 는 0 고정 유지**). 호스트는 `checks.py` 에 `check_imu_read()` 를 추가한다.
3. **정리 파일 생성** — 두 가지를 따로 로그로 남긴다. ① 수평 정지 60초 ② 각도기 기준 0° · 15° · 30° 각 자세. 둘 다 `results/<날짜>/imu_2_1_3.csv` 에 모은다.
4. **결과 기록** — 다섯 개를 적는다.
   · `WHO_AM_I`(reg `0x00`) 값과 revision
   · 수평에서의 `az` (g 단위)
   · 각도기 기준 대비 **pitch · roll 오차(도)**
   · 정지 60초 동안의 **값 변동폭** (노이즈 · 드리프트)
   · 샘플링 주기
   → **기울기 값을 얼마나 믿을 수 있는가** — 이 오차가 `NFR-2.4` 전도 임계값(60°)과 `FR-6.3` LiDAR 스캔 게이팅의 근거가 된다.

**⚠️ `yaw` 를 방위로 쓰지 않는다.** 가속도계로는 수직축 회전을 볼 수 없어 0 으로 남긴다 (OI-23).
자이로 적분은 QMI8658 드라이버(`3.2.3`)에서 따로 다룬다.

# ⑥ `4.1.2` HAL 래퍼 (hal_mechdog) → 엑셀 `4.1`

1. **장치 설정** — 로컬 `MechDog V1.3` 설치본에서 벤더 파일 11개를 빌드 트리에 복사하고(**커밋하지 않는다**) `MECHADOG_ENABLE_ACTUATORS=1` 로 빌드한다. 로봇은 받침대에 올려 발이 뜨게 한 번 먼저 돌린다.
2. **코드 추가** — `hal_mechdog.*` 에서 MOVE · POSE · GAIT · ACTION 을 `HW_MechDog` API 로 매핑한다. 호스트는 `checks.py` 의 `check_actuators()` 가 이미 있으므로 `SKIP` → `PASS` 로 바뀌는지만 본다.
3. **정리 파일 생성** — `report.md` · `report.json` 과 함께 네 명령의 동작 영상을 남긴다.
4. **결과 기록** — 네 명령 각각의 동작 여부, 보행 제어 루프(50Hz) 유지 여부.
   → **서보가 실제로 돌고 그러면서 제어 루프를 방해하지 않는가**

# 코드 쓸 때 조용히 폐기되는 것 5가지

**예외가 나지 않고 폐기만 된다.** 시험 없이는 실기에서야 드러난다. 정본은 [`docs/PROTOCOL.md`](../docs/PROTOCOL.md).

1. **제자리 회전을 쓰지 않는다 (DR-11).** `MOVE` 는 호(arc) 조향이다 — 목표가 뒤면 **후진 호**(step 음수 + 조향 부호 반전)로 돌아선다.
   ⚠️ **«`step=0, angle≠0` 은 로봇이 할 수 없다» 는 틀렸다 (2026-09-22 실측).** 실제로는 제자리에서 돈다(7.37 도/s · 양방향 · 육안 확인). **폐기되지도 않는다** — 그래서 이 항목은 «조용히 폐기되는 것» 이 아니고, 쓰지 않는 이유는 «못 해서» 가 아니라 **산포가 82% 라 신뢰할 수 없어서**다 ([ADR-11](../docs/DECISIONS.md#adr-11)).
2. **`ts` 는 정수 밀리초다.** `time.time()` 을 그대로 실으면 규칙 ⑤ 로 폐기된다.
3. **`STATE` 는 FSM 13종만.** 그 밖은 폐기 + WARN, **`AVOID` 는 내려보내지 않는다** (ADR-22).
4. **첫 전문은 `STOP` seq=1** (`Commander.open_session()`). 아니면 이전 세션의 최대 seq 를 넘을 때까지 **통째로** 폐기된다.
5. **Tier 1 을 호스트로 옮기지 않는다** (아키텍처 1.2). 초음파 · 전도 · 저전압은 로봇이 **보고했을 때만** 따라간다. LiDAR 는 호스트 센서이므로 예외다.

> 명령을 직접 조립하지 말고 항상 `host/behavior/commander.py` 의 `Commander` 를 쓴다.
> 시험에서는 **나가는 전문을 `CommandDecoder` 에 물린다** — 의도만 확인하면 "컨트롤러는 옳은데 전문은 틀린" 상태를 못 잡는다.
