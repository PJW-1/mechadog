# 음성 파이프라인 판정 구조 — 무엇이 규칙(결정론적)이고 무엇이 LLM인가

이 문서는 `voice_pipeline.py` 대화 루프의 **판정 경로 전체**를 정리한다.
핵심 원칙은 하나다: **판정·숫자·명령·신원은 코드가 결정하고, LLM은 코드가
못 잡은 나머지 자유 발화만 처리한다.** LLM 출력이 하드웨어에 도달하는 경로는
스피커(TTS)뿐이고, 그마저 기계·고장 답변에는 고지 문구를 코드가 덧붙인다.

```
모듈 마이크 → faster-whisper STT(한국어) → 정규화(공백·구두점 제거)
   │
   ▼  route_query() — 아래 순서대로 처음 맞는 경로 하나만 탄다
   ┌──────────┬────────────┬───────────┬─────────┬────────┬──────┐
   │ action   │ scenario   │ emergency │ factory │ status │ llm  │
   │ 로봇 명령 │ 고정 시나리오│ 비상 접수 │ MES 조회│ 상태읽기│ 자유 │
   │ 화이트   │ 35종        │ 로그+멘트 │ 5 테이블│ 실측값  │ 대화 │
   └──────────┴────────────┴───────────┴─────────┴────────┴──────┘
   │
   ▼  결정론적 답변 / LLM 답변(+machine_guard 고지) → Piper TTS → 모듈 스피커
```

## 0. 대화 게이팅 (라우팅 전 단계, 전부 규칙)

| 구분 | 인식 구문 | 동작 |
|---|---|---|
| 웨이크워드 | `메카독` `메카도` `메카닭` `메카도기`로 시작해야 함 | 접두어를 떼고 나머지를 질의로 받는다. 없으면 무시 |
| 대기 전환 | `그만` `꺼져` `대기해` `잠자` | standby 모드 — 듣기만 하고 대답 안 함 |
| 복귀 | standby 중 `메카독 시작/깨워/일어나/켜져` | active 복귀 + 확인 멘트 |
| 후속 대화 | 답변 후 **20초**(`FOLLOW_S`) 안, 3자 이상 발화 | 웨이크워드 생략 허용 — "A라인 생산량?" → "B라인은?"이 자연스럽게 이어짐 |
| 잡음 제외 | 3자 미만 / VAD 미감지 | 무시 |

- 정규화는 `[\s,.!?~…:'"·]` 제거뿐 — 띄어쓰기·말끝 흐림을 흡수한다.
- STT 도메인 바이어스(`STT_PROMPT`)로 "메카독/비상정지/순찰" 등 어휘를 whisper에 미리 알려 오청을 줄인다.

## 1. action — 음성 로봇 명령 (WBS 4.7.11, 화이트리스트)

`robotlink.match_action()` — 정규화된 발화가 **정확히 일치**하거나, 목록에 있는
명령 어미만 떼어내면 일치할 때만 실행한다. 부분 일치·유사어 없음.

| 발화(정규화) | 명령 | 발화(정규화) | 명령 |
|---|---|---|---|
| 비상정지·긴급정지·스톱 | `estop` | 순찰시작·순찰개시·순찰해 | `patrol_start` |
| 수동모드·수동제어 | `manual_on` | 순찰정지·순찰중지·순찰멈춰 | `patrol_stop` |
| 자동모드·수동해제 | `manual_off` | | |

- **명령 어미**: `해줘` `해주세요` `로전환해줘` `하세요` … 약 30종 + STT 오청
  어미(`해져` `해죠` `하죠` `했죠` `했어`)를 벗겨낸 뒤 일치를 본다.
  "비상정지해줘"는 명령이 되지만 `비상정지하지마`·`비상정지할까`는 목록에 없는
  꼬리라 **절대 명령이 안 된다** — 부정·의문이 명령으로 번역되는 것을 구조로 막는다.
- **의도적 제외**: `reset`(래치 해제)처럼 사람의 현장 확인이 필요한 명령은 음성
  경로에 없다. 로봇 런타임의 자체 안전 게이트(accepted 판정)도 그대로 탄다.
- 한계: 표의 5종 명령뿐. "충전소로 가" 같은 새 명령은 코드 추가 없이는 불가.

## 2. scenario — 고정 대본 실행 (WBS 4.7.7)

`scenarios.TRIGGERS`의 구문이 발화에 **포함**되면 해당 시나리오 함수가 돈다.
대본·판정은 PC 코드, 모듈 재플래시 불필요.

| 카테고리 | 트리거 예 | 시나리오 |
|---|---|---|
| 신원·보안 | `경비모드` `신원확인` | `guard` — 성명 청취 → `knowledge/직원명단.txt` 대조 → 확인/미등록 판정 (**암구호 인증의 실체**, LLM 미사용) |
| | `방문자확인` | `visitor_check` — 방문증 소지 여부 질의 → 규정 안내 |
| 안전 경고 | `안전모경고` `안전조끼경고` `보안경경고` `경고방송` | PPE 종류별 경고 방송 |
| | `제한구역` `전기위험` `화학물질` `금연` `촬영금지` | 구역별 경고 방송 |
| | `지게차경고` `하역경고` | 차량 작업 경고 |
| 화재·응급 | `화재대피` `대피방송` | `fire_evac` — 감지→대피→집결 3단 안내 |
| | `비상접수` | `emergency_response` — 위치 청취 → 접수 멘트 |
| 순찰·안내 | `순찰안내` `길막` `비켜` `순찰보고` `방문자안내` | 방송 / 목적지 청취 → `knowledge/` 검색 안내 |
| 일정·공지 | `교대안내` `식사안내` `점심안내` `점검안내` `출하안내` `안전수칙` `공지사항` | `knowledge/` 해당 문서 첫 문단을 읽어 안내 |
| 환경·기상 | `비온다` `우천` `춥다` `한파` `덥다` `폭염` | 기상 주의 방송 |
| 야간·훈련 | `야간순찰` `대피훈련` `훈련시작` | 안내 / 훈련 3단 방송 |
| 상태·정보 | `상태보고` `안전점검` `분실물` `누구야` `뭐하고있` | 텔레메트리 브리핑·체크리스트·고정 멘트 |

- 다회전 대화도 코드로만: `guard`는 무응답 시 1회 재질의, `emergency_response`는
  위치를 다시 묻는다. 그 이상의 문맥 추적은 없다.
- 관제에서도 같은 테이블을 실행: `POST /scenario {"name":"fire_evac"}`.

## 3. emergency — 비상 단어

`도와줘` `살려줘` `비상` `응급`이 발화에 포함되면: `emergency_log.txt`에 기록 →
"관제 센터에 전파했습니다" 고정 멘트. 전화·알림 같은 실제 외부 발신은 없고
기록+방송이 전부다. `비상정지`는 1순위 action이 먼저 잡고, `비상접수`는
scenario가 먼저 잡는다 — 순서가 의도된 것이다.

## 4. factory — 가상 MES 조회 (보조 기능, WBS 4.7.15~)

`factorylink.classify()`가 키워드 → MES 엔드포인트로 매핑하고, 답변은
**결정론적 템플릿**이 만든다(숫자 천단위·조사 처리·출처 꼬리표 포함). LLM 미개입.

| 질의 키워드 | 엔드포인트 | 답하는 것 |
|---|---|---|
| `생산량` `생산현황` `진행률` `생산목표` `목표대비` `몇개만들` | `/api/production` | 라인별 목표/완료/잔량/상태, 진행률 |
| `X라인` + `가동` `정지` `상태` `돌아가` `멈춰` `세워` | `/api/production?line=X` | 해당 라인 상태 |
| `라인상태` `라인현황` `가동현황` `어느라인` | `/api/production` | 전 라인 요약 |
| `출하` `납품` `납기` `배송일정` `출하일정` | `/api/shipments` | 앞으로 7일 이내 출하 |
| `작업지시` `지시서` `작업순서` `우선순위` `작업스케줄` | `/api/schedule` | 미완료 지시를 우선순위순 |
| `불량` `검사결과` `품질검사` `수율` `검사현황` | `/api/inspections` | 검사·불량 합계와 최악 로트 |
| `설비점검` `설비상태` `점검기록` `설비이력` | `/api/equipment` | 설비별 최신 점검 결과 |

- 데이터 소스: `factory_mes.py` — SQLite(`mes_demo.db`) + 읽기 전용 HTTP `:8095`.
  모든 응답에 `source`·`updated_at`·`stale`를 붙이고, stale 판정(기본 6h,
  `--stale-after`)은 서버가 한다. 답변 끝에 "demo-mes의 1시 16분 자료입니다"가 붙는 이유.
- 미등록 라인 질의에는 등록 라인 목록을 알려준다. MES 다운 시 "연결할 수
  없습니다"로 응답하고 루프는 산다.
- 실제 MES가 생기면 `factorylink.DEFAULT_BASE`(또는 `--mes-api`)만 실 API로
  교체한다 — 음성 쪽 코드는 그대로다.
- 한계: 키워드 포함 매칭뿐 — `생간량` 같은 STT 오청은 못 잡아 llm으로 새고,
  발화에서 숫자 파라미터를 뽑지 못한다("9월 이후 출하"라 해도 항상 7일 창).
  라인 표기는 알파벳 한 글자 + `라인` 형태만 인식한다.

## 5. status — 로봇 상태 읽기 (WBS 4.7.10)

`배터리` `상태` `온도` `보고` `잔량` `충전` 중 하나가 들어가면
`GET /api/telemetry`의 **실측값**을 읽어 "배터리 8.54볼트, 내부 온도 41도,
동작 상태 IDLE, 대응 단계 L0" 식으로 말한다. 관제 다운이면 연결 불가를 말한다.

## 6. llm — 자유 대화 fallback

위 다섯 경로 어느 것도 안 잡은 발화만 여기로 온다.

- **모델**: `llama-cpp`로 로컬 GGUF 챗 모델(개발본은 EXAONE 계열)을 GPU에 올려
  `create_chat_completion`. `max_tokens=96`, `temperature=0.6`, 대화 history 유지.
- **시스템 프롬프트**: 메카독 페르소나 + "한두 문장, 이모지·마크다운 금지,
  참고 자료 밖 내용은 '확인되지 않은 정보'라고 답할 것".
- **경량 RAG**: `knowledge/*.txt`(25종 — 안전규정·화재대피·지게차수칙·
  직원명단·식단표 등, 전부 합성 데모 데이터)를 쿼리와 2-gram 겹침 점수로
  상위 3개·최대 1200자를 `[참고 자료]`로 프롬프트에 붙인다. 벡터DB 없이
  파일 추가만으로 지식이 늘어나는 구조.
- **machine_guard**: 답변 생성 후, 질의가 기계·고장 계열(`고장` `수리` `설비`
  `기계` `진단` `안돌` `멈췄` `이상소리`)이면 "실제 고장 판정과 수리는 담당
  기술자가 수행해야 합니다" 고지를 코드가 붙인다 — LLM이 빼먹어도 항상 붙는다.

## 7. 경계선 — 무엇을 LLM에 맡기지 않는가

| 항목 | 담당 | 이유 |
|---|---|---|
| 로봇 동작 명령 | action 화이트리스트만 | LLM 자유 텍스트가 명령이 되는 경로 없음 (3.8.2 원칙) |
| 신원·암구호 판정 | 명단 대조 규칙 | LLM 판단으로 출입 허가하지 않음 (ADR-31) |
| MES 숫자·상태 | factorylink 템플릿 | LLM의 숫자 생성·뭉개기를 막음 |
| 로봇 실측값 | telemetry API 읽기 | 지어낸 배터리 잔량 방지 |
| 데이터 신선도 | 서버측 stale 판정 | 오래된 값이면 "확인 불가"로 고정 응답 |
| 기계·고장 안내 | machine_guard 고지 | 매뉴얼 안내와 실제 수리 책임을 구분 |

## 8. LLM으로 더 할 수 있는 것과 방법

현재 LLM 경로는 "규칙이 못 잡은 질문에 knowledge 문서 근거로 짧게 답하는"
fallback이다. 확장 방향(해도 되는 것과 구조상 하면 안 되는 것):

- **지식 추가(가장 쉬움)**: `knowledge/`에 `.txt`를 넣으면 끝 — 재시작 시
  자동 로드, 2-gram 검색에 바로 탄다. 실사 매뉴얼·SOP를 넣는 용도.
- **검색 품질**: bigram 겹침은 데모 규모용이다. 문서가 수십~수백 개로 늘면
  임베딩 검색(벡터 유사도)으로 `retrieve()`만 교체하면 된다 — 호출부는 한 줄.
- **파라미터 있는 질의**(예: "다음 주 이후 출하"): 지금은 발화에서 숫자·날짜를
  못 뽑아 고정값으로만 답한다. LLM에 function-calling/구조화 출력을 얹어
  *의도+파라미터만* 추출하게 하고 실행은 기존 엔드포인트로 보내는 구조가
  다음 단계다 — 단, **추출과 실행을 분리**해 LLM이 만든 문자열이 API에
  그대로 가지 않게 해야 한다(화이트리스트 원칙과 같음).
- **응답 품질**: `max_tokens`·`temperature`·SYSTEM 문구 조정, 더 큰 GGUF로
  교체(VRAM 예산은 파일 상단 주석 참조). 출력을 JSON/문법으로 제약하는
  grammar 옵션도 llama-cpp가 지원한다.
- **절대 옮기지 않을 것**: estop 해제·신원 판정·MES 수치 생성을 LLM에 넘기는
  방향 — 위 표의 경계를 깨는 일이라 채택 근거가 필요하다.

## 9. 설정 DB 오버레이 — `voice_store.py`

암구호형 트리거·명단·설정을 코드 수정 없이 운영 중에 바꾸는 층이다.
`voice_data.db`(SQLite)가 있으면 테이블 내용이 코드 기본값보다 우선하고,
없으면 코드 기본값 그대로 — **DB는 필수가 아니라 오버레이**다. git에 올라가지
않으며 `python voice_store.py --seed`로 코드 기본값을 옮겨 만든다.

| 테이블 | 내용 | 정본 | 소비자 |
|---|---|---|---|
| `keywords` | wake·sleep·resume·emergency·status·machine 단어 | DB 행 있으면 DB | `voice_pipeline`·`robotlink` |
| `command_endings` | 벗겨낼 명령 어미 | 〃 | `robotlink.match_action` |
| `action_commands` | 발화 구문 → (로봇 명령, 확인 멘트) | 〃 | `robotlink` |
| `scenario_triggers` | 발화 구문 → 시나리오 이름 | 〃 | `scenarios.match_trigger` |
| `factory_rules` | 키워드 → MES 엔드포인트 규칙 | 〃 | `factorylink.classify` |
| `roster` | 신원 확인 직원 명단 | DB 행 있으면 DB, 없으면 `knowledge/직원명단.txt` | `scenarios.sc_guard` |
| `phrases` | 응답 문구 **추가분** | 기본 문구는 코드 불변, DB는 얹기만 한다 | `phrases.merged` |
| `settings` | follow_s·stt_prompt·API 주소·암구호류 키-값 | 키 있으면 DB 값 | `voice_pipeline` 등 |

경계는 그대로다:

- **보호 구문**: `비상정지`·`긴급정지`·`스톱`(PROTECTED_ACTIONS)은 DB가 지우거나
  다른 명령으로 바꿔도 코드 기본값이 항상 합쳐진다.
- **DB가 바꾸는 것**: "무슨 말이 트리거인가"뿐. 명령 실행은 robotlink의
  화이트리스트와 로봇 런타임 게이트가 계속 판정하고, 신원 판정·MES 수치·
  stale 판정도 코드가 한다. DB 행으로 새 시나리오를 만들 수는 없다 —
  `scenario_triggers`는 기존 SCENARIOS 키로만 매핑된다.
- **민감 값**: settings 키가 `pass|secret|token|code|key`를 포함하면
  `--set` 에코와 `--dump` 출력에서 `***`로 가린다(평문 로그 방지).
- **장애 시**: DB 없음·테이블 없음·SQL 오류는 전부 코드 기본값으로 fallback —
  저장소 문제가 음성 루프를 죽이지 않는다.

### 원격 백엔드 — Supabase

`SUPABASE_URL` + `SUPABASE_ANON_KEY` 환경변수가 있으면 읽기는 Supabase
PostgREST가 우선이다. 사슬은 `Supabase → 로컬 voice_data.db → 코드 기본값` —
원격이 실패하거나 테이블이 비어 있으면 다음 단계로 내려간다(테이블 통삭제
실수가 명단을 즉발로 날리지 않게). 매 턴 왕복을 막는 TTL 캐시는
`VOICE_STORE_TTL`초(기본 60). 쓰기(`--remote` 플래그)는
`SUPABASE_WRITE_KEY`(service role)가 필요 — 음성 PC에는 anon 키만 둔다.
테이블 스키마와 anon 읽기 RLS 정책은 `supabase_setup.sql` 참조.

가상 MES도 같은 구조다: `factory_mes.py`를 `MES_BACKEND=supabase`로 띄우면
같은 Supabase 프로젝트의 MES 테이블을 읽는다. `/api/*` 응답 계약
(`data`·`source`·`updated_at`·행 단위 `stale`·`unknown_line`)은 백엔드와
무관하게 동일 — 이 판정은 서버가 아니라 이 코드가 한다.

운영 CLI:

```bash
python voice_store.py --seed                  # 코드 기본값으로 생성/초기화
python voice_store.py --dump                  # 전체 테이블 확인(민감값 마스킹)
python voice_store.py --set follow_s 30       # 설정 변경
python voice_store.py --add wake 메카독이      # 웨이크워드 추가
python voice_store.py --add-roster 홍길동      # 직원 명단 추가
python voice_store.py --del-roster 김민수      # 퇴사자 삭제
python voice_store.py --add-phrase greeting "안녕하세요, 현장지원 로봇입니다."
# 같은 명령에 --remote를 붙이면 Supabase에 적용 (SUPABASE_WRITE_KEY 필요)
python voice_store.py --seed --remote         # 코드 기본값을 Supabase로 업서트
```

## 10. 운영 메모

- 기동: `start_voice.ps1` (COM5 + 관제 API `:8090`, MES `:8095` 자동 기동).
- 관제 API: `/status` `/say` `/scenario` `/scenarios` `/phrases` `/mode`
  `/transcript` `/report` — 링크는 메인 루프 단독 소유, 웹 요청은 큐 직렬화.
- 이력: `logs/voice-YYYY-MM-DD.jsonl` 일자별 저널 → `/report` 당일 요약.
  비상 발화는 `emergency_log.txt`에도 별도 적립.
- COM5는 임시 전송층 — 목표 경로는 모듈 ↔ 로봇 4핀 I²C ↔ ESP32 ↔ Wi-Fi
  (4.7.9). 이 문서의 판정 구조는 전송층과 무관하게 그대로다.
- 실기 왕복 확인(2026-09-17, COM5): "메카독 A라인 생산량 알려줘" → factory
  경로 결정론적 답변 확인. 알려진 빈틈: STT 오청(`생간량`)이 키워드를 빠져
  llm로 새는 것 — `voice_store.py --add`로 오청 변형을 factory_rules에
  올려 흡수할 수 있다.
