# PPE v23b: 라벨 정리 후 밑바닥 재학습 개발 후보

[모델·평가·출처 릴리스](https://github.com/PJW-1/mechadog/releases/tag/ppe-v23b-candidate-20260924)

안전모/미착용, 조끼/미착용, `person_down` 을 함께 학습한 YOLOX-S 후보다.
기본 운영 모델은 `ppe-v3` 로 유지한다. **실기 승인이 아니며, 사전에 정한 승격 조건 4개 중
1개를 통과하지 못했다**(아래 «통과하지 못한 조건»).

⚠️ **이 가중치는 `CC BY-NC-SA 4.0` 이다 — 비상업 용도 한정.** 학습 자료에
UR Fall(CC BY-NC-SA 4.0) 프레임 2장이 들어 있다. `ppe-v12` 후보는 UR 을 진단에만 썼으므로
이 점이 다르다. 받기 전에 `NOTICE.txt` 를 읽는다.

## 받기

```bash
python tools/fetch_models.py --ppe-candidate
```

```bash
python tools/fetch_models.py --ppe-candidate --check
```

모델과 `NOTICE.txt` 를 `models/candidates/ppe-v23b/` 에 저장하고 크기와 SHA256 을 검증한다.
`models/ppe.onnx` 와 운영 설정은 바꾸지 않는다. 비교 시험에서만 별도 모델 경로를 지정한다.
입력은 기존 YOLOX 전처리, float32 `[1,3,640,640]`, 출력은 raw `[1,8400,10]` 이다.
클래스 순서는 `helmet, no_helmet, vest, no_vest, person_down` 이다.

모델은 35,795,331 바이트이며 SHA256 은
`5b35eb4f909dfdd995b3c7f805467a44319d96a89af740f96f7b375d8d836089` 다.

## 왜 다시 학습했나

`v13`·`v16`·`v20` 은 전부 `v12` 가중치에서 미세조정했다. 그런데 학습 자료의 상당수가
**부분 주석**이었다 — 사람에게 맨머리나 몸통이 보이는데 박스가 없는 사진이 학습 1,925장 중
793장이었다. 그런 사진은 모델에게 «맨머리·몸통 = 배경» 을 가르친다. 그 편향이 `v12`
초기값에 들어 있으므로 미세조정으로는 벗어나기 어렵다.

이 후보는 **COCO 사전학습에서 60 epoch** 으로 새로 학습했고, 자료도 운영 분포에 맞췄다.
런타임(`host/vision/ppe_detector.py`)은 **사람 크롭 한 명**에만 추론하므로 군중 사진 대신
**머리·몸통이 모두 라벨된 사람 크롭**을 쓴다. 학습 1,669장 / 3,737박스.
