# 카메라 프레임 실측 — 공유기 근접 배치 + PC 유선 (2026-09-14)

공유기를 로봇·카메라와 같은 방으로 옮기고 PC 를 랜선으로 붙인 뒤 스트림 수신률을 쟀다.
카메라는 그대로 Wi-Fi 다.

카메라만 읽었다. 로봇 명령(MOVE/POSE/STOP/RESET_SAFE) 미송신, COM 접근 없음, 플래시 쓰기 없음.
카메라 프로파일은 런타임 `/profile` 로만 바꿨고 시험 후 원래 값(VGA·상한 25)으로 되돌렸다.

## 구성

| 항목 | 값 |
| --- | --- |
| 카메라 | XIAO ESP32S3 · OV3660 · Wi-Fi · **RSSI −14 dBm** |
| PC | 이더넷(랜선). 스트림 연결의 소스 IP 로 유선 경로 확인 |
| 도구 | `tools/camera_link_check.py` (카메라 전용) |

09-12 최적화 측정 당시 RSSI 는 −64 ~ −50 dBm 이었다.

## 확인된 것

### 1. 지금 병목은 무선이 아니라 카메라 파이프라인이다

상한을 25 → 40 으로 풀어도 25.24 fps 에서 멈춘다. QVGA 로 내려 JPEG 를 6.4 KB(1/3)로
줄여도 27.63 fps 로 10% 만 오른다. 해상도를 1/4 로 줄였는데 fps 가 그만큼 안 오른다는 것은
**전송이 아니라 센서·인코딩이 약 25~28 fps 에서 한계**라는 뜻이다.

무선 여유는 충분하다 — 25 fps × 17 KB ≈ 3.4 Mbps, `discarded`·`resyncs` 0.

2026-09-08 검수 때 장치 로그가 27.5·27.8 fps 였던 것과도 맞는다.

### 2. 두 번째 접속은 0 프레임을 받는다

`:81/stream` 에 A 를 먼저 열고 8초 뒤 B 를 붙였다. 2회 반복, 같은 결과다.

| | 1회차 | 2회차 |
| --- | --- | --- |
| A — B 접속 전 | 21.0 fps | 22.71 fps |
| A — B 가 붙어 있는 동안 | 23.86 fps | 21.86 fps |
| **B (나중 접속)** | **0.0 fps · TimeoutError** | **0.0 fps · TimeoutError** |

먼저 붙은 쪽은 **전혀 영향받지 않고**, 나중에 붙은 쪽이 통째로 굶는다. 나눠 갖지 않는다.

`firmware_xiao_vision/README.md` 의 "두 번째 접속은 대기한다"를 클라이언트 입장에서 보면
**죽은 스트림과 구분되지 않는다** — 한 장도 못 받고 타임아웃으로 끝난다. 화면이 검게
비어 있을 때 카메라 고장이나 네트워크 문제로 오진하기 쉬우므로 먼저 다른 수신자를 의심한다.

공유기를 옮겨도 이 제약은 그대로다.

## 상한을 올릴 것인가 — 결정 사항

상한 25 는 실측 파이프라인 한계(약 25.2)보다 낮아 **현재 자신이 제한 요인**이다.
`config.yaml` 의 `vision.stream_fps_limit` 를 30 으로 올리면 약 **+5%**(23.8 → 25.2) 나온다.

그런데 이 저장소는 상한의 목적을 명시해 두었다:

> 상한을 두는 목적은 낮추는 것이 아니라 **예측 가능하게 만드는 것이다.**
> 상한이 없으면 JPEG 크기가 화면 내용에 따라 변하고 발열에 따라 fps 가 흘러서,
> 명령 타임아웃(300ms) 대비 최악 부하를 계산할 수 없다.

즉 상한을 올리면 최악 대역폭 가정도 같이 올라간다. **+5% fps 와 부하 예측 가능성의
맞바꿈이므로 이 문서에서 값을 바꾸지 않았다.** 팀이 판단할 사항이다.

올리기로 한다면 `config/config.yaml` 의 `vision.stream_fps_limit` 한 곳만 바꾸면 된다
(펌웨어 기본값 25 는 폴백이라 재설치가 필요 없다).

## 남는 것

- 카메라 **단독 스트림 수신률**이다. 추론을 붙였을 때·보행 중·장시간 값이 아니다.
- 통제된 A/B 가 아니다. 공유기 이동·PC 유선·거리가 함께 바뀌어 각 기여도를 분리하지 못했다.
  PC 를 Wi-Fi 로 되돌린 대조군은 재지 않았다.
- 기체 1대의 카메라 1대다. 다른 기체에 값을 복사하지 않는다.
