## 2. 보고서 3장에 넣을 설계 설명

LD19는 독립 ESP32 DevKit의 UART2(RX GPIO16, 230400 bps, 8N1)에 연결한다.
중계는 로봇 메인보드를 거치지 않고 약 72점의 부채꼴 청크를 JSON SCAN
데이터그램으로 UDP 5201에 송신한다. 한 데이터그램은 한 회전 전체가 아니다.
`boot_id`는 부팅을, `seq`는 부팅 안의 데이터그램 순서를 구분한다.
센서 회전 약 9.90 Hz와 `/scan` 9.919 Hz는 9/29 실측 인용값이며 UDP 패킷
빈도와 구별한다. 근거: D §6・§6절 질문1, [중계 README](../../firmware/lidar_relay/README.md),
[LiDAR 규약](../PROTOCOL_LIDAR.md).

호스트 LidarFeed가 5201의 유일한 수신자로 원본 기록, 5203 바이트 복사,
패킷 검증, 근접 비상정지 판정, 회전 조립을 맡는다. 주 측위는 호스트
PatrolController의 스캔 정합과 전역 재측위다. 측위 지도와 항법 점유격자를
구분하며, 10-06 시연 동선은 `nav.relaxed_follow`로 **동선 점 추종 + LiDAR 빈 방향 선택**을
사용한다. A*・막힘 기억・AG/AH 복구 관문은 코드에 보존되지만 이 시연 동선에서는
사용하지 않는다. 근거: U 첫 절・§7, D §6~8,
[LidarFeed](../../host/telemetry/lidar_feed.py), G `b0ea384`.

ROS2 컨테이너의 scan_bridge는 5203 청크를 회전별로 조립해 `/scan`을 발행한다.
slam_toolbox와 RViz는 관측・지도 작성 도구이며, 현재 시연 런타임의 주 측위와
구별한다. **5204 ODOM 개체별 추가 구현・검수 작업은 폐기됐으나 기존 송신・브리지・tf 코드는 보존**한다.
**5205 MAP_POSE 반환은 시연 `host.runtime`에서 사용하지 않는다**.
별도 `tools/ops/patrol_run.py`의 MAP_POSE 소비 경로가 있다는 것과 혼동하지 않는다.
근거: D §6~8, U §8, [ROS2 README](../../docker/ros2/README.md),
[런타임](../../host/runtime.py), [WBS](../internal/WBS.md).

## 6. 합격 기준과 보고서 서술

A는 10-05 22:13 측정 전에 고정했다. 앞 물체 접근 3/3 접촉 없이 정지・몸체 여유
5 cm 이상, 한 바퀴 1~2회 4구역 도착・충돌 0・비의도 비상정지 0,
일부 막힘 3/3 우회・알림, 완전 막힘 1회 건너뜀・알림, 별도 600초
LINK_LOST 0 시험이다. 일반 시험에 시간 기준을 두지 않는 것과 별도 10분 시험을 구별한다.
기준을 사후에 낮추지 않으며, 따라가기의 완전 막힘 대기는 기존 건너뜀 기준 충족으로
세지 않는다. 충돌・비의도 비상정지・몸체 여유가 모두 확인된 종합 합격은 이 자료만으로
판정할 수 없다. 기존 H3 누적 운용 승인 이력은 신규 10분 연속 실기 통과와 구별한다(D §6절 질문2).

5장 사례 후보는 D §14의 slam_toolbox lifecycle 전이 누락(기존 PR #383),
5201 포트 경쟁→5203 복사(기존 PR #304・#376)와 U §14의 따라가기 도입・IMU
스캔 거절이다. 따라가기 전후 완주는 U 작성 시점 기준 0→2회이며 야간 이어가기는
별도 기록이다. IMU 근본 해결・지연 개선량은 미측정이다. 현장 신규 커밋의 PR 번호는
제공 근거에 없어 만들지 않는다.

6장 편집용 문안(D §15, 개인 소감 확정 아님): “LiDAR 패킷이 들어오고 ROS2 노드가
실행되는 것만으로는 정상 스캔과 올바른 위치가 보장되지 않았다. 원본 스캔・측위・명령・안전
전이를 같은 시각으로 남기니 수신 문제, 지도 오정합, 주행 정책 문제를 나누어 볼 수 있었다.
다음에는 같은 기록의 정합 점수와 별도 기준점으로 확인한 실제 위치 정확도를 구분해 검증하겠다.”
