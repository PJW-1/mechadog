## 1. 이 프로젝트가 무엇인가 — 세 문장

**Hiwonder MechDog · Advanced Kit(4족 보행 로봇) 3대에 자율 경비·산업안전 점검 스택을 얹는다.**
로봇이 구역을 순찰하며 **침입자 인지·인증**과 **보호구(안전모·조끼) 미착용 점검**을 한 번에 수행하고,
**사이클 간 물체 변화**를 비교해 없어지거나 새로 생긴 것을 찾는다.

**고정 CCTV 로 되는 일이면 로봇을 만들 이유가 없다** — 로봇은 시점을 바꾸고, 가까이 가서 다시 보고,
대응한다. 특히 카메라가 지면 15cm 에 있어 **머리가 잘리면 자세를 올려 다시 본다**(FR-9.2.2).
이것이 고정 카메라가 할 수 없는 일이며 프로젝트의 정당성이다.

## 2. 확정된 것

### 팀 · 일정

| 인원 | 담당 | 대응 WBS `R` | 원공수 |
| :--- | :--- | :---: | ---: |
| **L1 · L2** | 펌웨어 · 하드웨어 · 온보드 안전로직 · 펌웨어 CI + 공간·항법 | **A** + 3.9 + 5.4.1 | **23.0** |
| **S · 팀장** | 비전 · PPE · 변화감지 · 인증 · FSM · 통신 · 로깅 · 대시보드 · 시험 | B·C 중 위 이관분 제외 | **47.5** |

**3인 · 4주 · 총 70.5 M/D.** 현재 배정은 팀장 총량도 과부하이므로 M1 통과 직후 이관 담당을 확정하고,
M2 착수 전 실제 진척 기준으로 다시 산정한다. 트리거와 이관 대상은 [WBS 담당자 기준](WBS.md) 절 참조.

### L1 · L2 — Phase 2 착수 전 Phase 1 책임 범위

**L1·L2는 이 기간에 한 팀으로 움직인다.** 담당은 로봇 위에서 실행되는 모든 것과 실물
검증이다. 목표는 Host PC가 **안전하게 움직이고 멈추며, 영상을 보내는 로봇**을 실제 장비로
쓸 수 있게 만드는 것이다. LiDAR·SLAM·ROS2는 M1과 V-9 검증 뒤 Phase 2에서 착수한다.

| 범위 | 완료 산출물 |
| :--- | :--- |
| **M0 실물 검증** | MechDog Wi-Fi/RSSI, IMU·초음파·배터리 전압 접근, `move()`·`transform()`·내장 액션, XIAO MJPEG fps·전원 안정성, 무게·부하·서보 오프셋을 측정해 [하드웨어 검증](HARDWARE_VERIFICATION.md)과 기기 프로파일에 기록 |
| **MechDog 모션·안전 펌웨어** | `firmware_mechdog_motion/` — Wi-Fi STA, UDP 제어 명령 8종 수신, `protocol_samples.jsonl` 기준 C++ 파서, 300ms 명령 타임아웃 정지, 3초 링크 두절 failsafe, 초음파 25cm 미만 반사 정지, 저전압·전도 대응, 10Hz 텔레메트리 송신 |
| **XIAO 비전 노드 펌웨어** | `firmware_xiao_vision/` — 카메라 초기화, VGA/QVGA MJPEG 스트림 송출, 프레임레이트·브라운아웃·재연결 안정화. **AI 추론은 여기서 하지 않고 Host PC가 맡는다.** |
| **펌웨어 품질·통합** | Arduino 빌드/정적 분석 CI, Python과 같은 골든 픽스처를 쓰는 C++ 파서 검증, `HW_MechDog` 라이브러리의 라이선스·벤더링 가능 여부 확인 |

**팀장에게 넘길 완료 기준**은 세 가지다.

1. Host PC의 UDP 명령을 실제 MechDog가 수신하고, 안전 정지·텔레메트리가 동작한다.
2. XIAO의 MJPEG URL을 Host PC가 안정적으로 수신할 수 있다.
3. 실측값과 개체별 설정이 문서·`config/devices/`에 기록돼 재현할 수 있다.

**지금 L1·L2 범위가 아닌 것**: `host/`의 통신 Python·config 로더·로깅, 사람/PPE/변화 감지, FSM·인증, 대시보드, LiDAR·SLAM·ROS2.

### 하드웨어 (Track A 전제)

| | 확정 |
| :--- | :--- |
| 로봇 | **Hiwonder MechDog · Advanced Kit · 3대** — 약 560g · 8 DOF · 214×138×126mm. ⚠️ **`MechDog AI`(711g · 3DOF 팔 · WonderLLM) 와 `MechDog Pro` 는 다른 제품이다.** 무게가 151g 차이나므로 그쪽 스펙을 인용하면 부하 계산과 LiDAR 탑재 판정이 전부 틀어진다 |

| ⚠️ LiDAR 배선 | **핀 물리 순서를 1차 출처로 확인하지 못했다.** `P5V` 와 `GND` 를 바꿔 꽂으면 즉시 파손된다. 케이블 색은 판매처마다 다르므로 **반드시 LiDAR 기판의 실크 표시를 눈으로 대조**한 뒤 결선한다 |
| 중계 MCU | **ESP32-DevKitC V4** — WROOM-32E · 38핀 · USB-C · 핀 기장착 |

| RX 핀 | **GPIO16** (UART2). `U0RXD`(GPIO3)를 쓰면 업로드가 막힌다 |
| 전원 | **보조배터리 5,000mAh 2구 · 3인 동일 사양.** LiPo·승압·충전 모듈 전부 제외 |
| 조립 | **전 과정 납땜 0** |

## 3. 지금 바로 시작할 수 있는 것 — 아무도 기다리지 않는다

**하드웨어 발주 전이지만 세 사람 모두 착수 가능하다.**

| 인원 | 첫 작업 | 왜 지금 |
| :--- | :--- | :--- |
| **L2** | `2.1.x` 하드웨어 검증 → **`2.2.1` 부하 테스트** | **부하 테스트가 곧 발주 판정이다** |
| **L1** | `setup.ps1` → `5.1.1` Arduino 환경 → **`2.1.1` Wi-Fi 확인** → `4.1.1` | 로봇은 이미 있다 |
| **S** | ~~`3.1` 프로토콜~~ ✅ → ~~**`6.1.1` 목업**~~ ✅ → **`4.4.1` config** ← 현재 → `3.4` FSM | 픽스처가 이미 있다 |

> **`2.1.1`(메인 ESP32 Wi-Fi 가용 여부)이 첫 관문이다.** 실패하면 `4.1.1` 을 다시 써야 하고
> UART 중계가 추가된다(+2.0 M/D, 가정 A-1). **펌웨어 개발의 첫 작업으로 둔다. 30분이면 된다.**

> **팀장이 목업(`6.1.1`)을 먼저 만드는 것이 핵심이다.** 목업이 있으면 펌웨어 없이 호스트를 개발하고,
> 픽스처가 있으면 호스트 없이 파서를 검증한다. **0.5 M/D 투자로 3인이 완전히 독립된다.**

## 5. 발주 대기 — 무료로 먼저 할 것

| # | 항목 | 소요 |
| :-- | :--- | :--- |
| 1 | 보조배터리 **2구 동시 출력** 확인 | 5분 |
| 2 | **최종 구성 약 200~235g 을 마스트 높이에서** 이고 보행 | 30분 |
| 3 | 반방전 · 선회 · **10분 연속** 반복 | 30분 |

> **2번이 발주 판정이다.** 약 600g 을 이고 걷는 것이 확인되었으나(RISK-02, 잠정) **측정 조건이
> 기록되지 않았다.** 무게중심이 올라가면 결과가 달라지므로 마스트 높이에서 재확인한다.

**발주 전 확인 2건** — 케이블 스펙에 `ZH` / `1.5mm` 표기 · 끝단이 **낱개 암 4개**인지.

## 9. 알아두면 헤매지 않는 것들

프로젝트를 처음 보면 **틀리기 쉬운 지점**만 모았다. 전부 문서에 근거가 있다.

| | |
| :--- | :--- |
| **측위 결정이 늦어도 착수는 안 막힌다** | Phase 1 의 P1 7종은 측위를 쓰지 않는다. 변화 감지조차 마커 한 장이면 된다 |
| **로봇은 걷는 사람을 못 따라간다** | 10~30cm/s 대 120~150cm/s. **판정 대상은 정지한 작업자**다 (FR-9.2.0) |
| **자세를 올린 상태로는 이동할 수 없다** | 전방 지면이 안 보인다. 대상이 움직이면 루프에 빠지므로 재시도 상한이 있다 (FR-9.2.4) |
| **ArUco 마커와 ARCore 앵커는 다르다** | 마커는 인쇄물, 앵커는 가상 좌표. 구역 마커는 Phase 2 에서 불필요해지지만 **사원증은 대체 불가** |
| **눈 LED 는 장식이 아니다** | 관측 가능한 상태 출력이며 디버깅 수단이다 |
| **L3 는 관리자 확인으로만 해제된다** | PPE 위반·물체 변화는 인증할 주체가 없다 |
| **`FR-8.0` 은 Phase 1 전용 우회 수단** | 측위가 확보되면 폐기된다 |
