# WonderEcho v34 — 4핀 내부 브리지 복구 시험용

상태: 소스 구현·PC 회귀 시험·CI1302 컴파일·공식 패키징 완료. **기기 미설치, 실물 미검증.**

이 후보는 CI1302의 UART1에 공장 브리지 패킷 `AA 55 type id FB`를 복원한다. UART0은 **921600bps 진단 로그 전용**이며 기존 WEC1 녹음/PC 음성 재생은 비활성이다. 이 후보를 USB 대화 기능까지 포함한 완성본으로 사용하지 않는다. PC의 STT·TTS·LLM 모델과 기존 성공 이미지 latest/v27은 변경하지 않았다.

## 변경

- UART1 115200/open-drain 초기화와 인식 결과 송신, 방송 요청 수신을 분리된 RTOS 큐/태스크로 연결한다. 잘못된 SDK native IIC0는 비활성화한다.
- 분할·연속 패킷, 잘못된 type/tail, 100ms 프레임 중단과 tick wrap에 대응한다. 큐는 8개이고 500ms가 지난 이벤트는 폐기한다. UART TX FIFO 대기는 20ms로 제한한다.
- 지원 범위는 검증한 명령 ID 1/2/3/4/9/10/11/12/26/27/28/29/30, 일반 방송 ID 1~5다. 전체 공장 명령 300개 호환으로 주장하지 않는다. 내부 ID와 외부 ID를 명시 표로 변환하며, 다른 명령표가 들어가면 초기화를 거부한다.
- 웨이크/학습/알 수 없는 ID는 로봇 명령으로 발행하지 않는다. 브리지 수신 방송은 인식 송신으로 되돌리지 않는다. SDK 플레이어가 사용 중이면 방송을 거부한다.
- 플레이어 음량 이득은 최대 40으로 제한하며 영구 NV 설정을 바꾸지 않는다. 기존의 검증되지 않은 IDLE 기반 ASR 큐 강제 초기화 타이머는 이번 후보에서 끈다. SDK 간헐 재생 정체가 완전히 해결됐다는 뜻은 아니다.
- 로봇 별도 패치: 2=후진, 3=좌, 4=우, 29=MARCH로 정정한다. 이 패치는 Devin의 미게시 i2c-probe 작업본용이며 최신 dev에 자동 통합하지 않았다. 로봇에는 설치하지 않았다.

## 완료한 검증

- 실제 C 패킷/매핑 코드의 네이티브 테스트: 정상 골든 프레임, 분할·연속·손상 후 복구, timeout/tick wrap, 16비트 내부 ID 대조, 웨이크·방송의 잘못된 명령 발행 방지, 잡음 100,000바이트 후 복구 통과.
- 18개 매핑이 공장 리소스의 두 모델 그룹과 모두 일치하며 중복 없음을 확인.
- 수정된 실제 로봇 dispatcher를 가짜 버스·모터에 연결한 C++ 시험: 전진/후진/좌/우/정지, 명령 이름, 안전 조건과 OTA 미확정 시 실행 거부, 미지원 ID 무동작 통과. 실제 로봇 보행 시험이 아니다.
- CI1302 GCC 컴파일/링크 통과. 새 브리지 C 두 파일은 `-Wall -Wextra -Werror`. 벤더 원본의 기존 경고는 남아 있으며 빌드 전체가 경고 0이라는 뜻은 아니다.
- 공식 merge의 `[0]code.bin`과 `[1]code.bin` 두 구성요소 바이트를 검사했다. 공장 부트·ASR·DNN·voice·user 리소스/배치 및 NV 배치 보존 확인. user code 150,600B, 전체 이미지 1,969,737B.

## 다음 실물 단계

1. 4핀을 분리한 모듈 USB에 PACK_UPDATE_TOOL로 위 파일을 설치한다. 09-19 조회에서 로봇은 COM8(실제 부팅 로그 확인), 다른 장치는 COM5다. COM5 WEC1 신원 응답은 없었으므로 현재 설치 버전은 미확인이다. 재연결 시 번호를 다시 확인한다.
2. 업데이트 도구를 닫은 다음 모듈 UART0@921600에서 `[WE-BRIDGE] build=3401 ready`와 `init_result=0`을 확인한다. 실패 시 다른 명령을 보내기 전에 로그를 보존한다.
3. 모듈 USB를 제거하고 전원을 끈 상태에서 4핀을 로봇에 연결한다. 초기 검증은 로봇 구동 차단 상태에서만 한다. 외부 0x34 및 reg0x64 결과를 확인한다.
4. 깨우기 후 명령별 결과 ID를 확인하고 reg0x6E의 표준 방송으로 실제 발화를 확인한다. ACK/큐 수락/콜백은 청취 성공과 구별한다.
5. 이 경로가 확인된 뒤 UART0 오디오와 UART1 브리지의 플레이어 소유권을 통합하고 기존 USB 오디오를 회귀한다. 4핀 ID 통신은 PCM 스트리밍이 아니며 PC/LLM 오디오 중계 완료로 표시하지 않는다.

SDK 사본, 로컬 빌드 스크립트, 설치 이미지와 모델은 Git 게시 대상이 아니다. 이 작업 폴더의 prepare/build/package 도구에는 개인 PC 경로가 있으므로 게시 전에 경로 인자로 정리해야 한다. 현재 PR·커밋·배포 없음.
