# 쓰러짐 규칙 판정 실기 확인 (2026-09-23 · `mechdog-01` · WBS 4.8.3)

`FallenGate`(종횡비 ≥ 1.5 이면서 정지 3초) 가 실제 카메라 시점에서 누운 사람을 확정하는지, 앉은 자세를 잘못 확정하지 않는지 확인한 기록이다.

- 기체 `mechdog-01` · XIAO `mount_rotation 180` (`orientation_applied rot=180` 확인) · 카메라 높이 약 15cm
- **경비 모드 · 래치(`FAILSAFE`) 상태**로 카메라만 봤다. 로봇은 움직이지 않았다. 쓰러짐 규칙은 모드와 상관없이 같은 코드로 돌기 때문에 판정 자체는 경비 모드에서 확인할 수 있다.
- 공장 모드 경로(L3 상승 · 전용 문장 · PPE 보류)는 `models/ppe.onnx` 가 없어 실기로 띄우지 못했다 → 단위 시험으로만 확인했다.
- 조명: 밤 실내. 카메라 도착 프레임이 초당 15~22 로 낮 시간(21~24)보다 적었다.
- 커밋 해시는 `dev` 에 리베이스한 뒤의 것이다. 실측 때 돌린 코드와 내용은 같다.
- 원자료 `logs/*.jsonl` 은 `.gitignore` 대상이라 로컬에만 있다. 시각은 KST. 피험자가 찍힌 사진은 커밋하지 않았다.
- 점수 확인용 탐침: 대시보드 스냅샷을 임계값 0.05 로 다시 검출했다(약 2.3초 간격). 탐침 사진은 확인 뒤 지웠다.

## 찾아서 고친 것

1. **런타임이 확정 엣지를 놓쳤다** (`64f1fab`). 워커는 25fps, 런타임 틱은 10Hz 라 `changed` 가 실린 프레임이 읽히기 전에 덮어써졌다. run1 에서 워커 확정 6회 중 4회가 사라졌다. 공장 모드였다면 L3 가 빠질 수 있었다. → `person` 게이트처럼 런타임이 `EdgeTrigger` 로 직접 본다.
2. **한 프레임만 빠져도 누적이 지워졌다** (`f511afd`). 15cm 저각에서 누운 사람의 `person` 점수가 0.26~0.85 로 임계값 0.5 근처를 오갔다. 박스가 빠지거나, 추적기가 같은 사람에게 새 ID 를 주면 3초 누적이 처음부터 다시 시작됐다. run1 에서는 확정 0.1초 뒤 풀렸고(23:23:39), run2 에서는 4분 동안 한 번도 확정되지 않았다. → `vision.fallen.gap_ms: 1000` 보다 짧은 공백은 누적·확정을 유지하고, 새 ID 라도 같은 자리(중심 20px 이내)면 같은 사람으로 본다. 모양·움직임 조건은 그대로 엄격하다.

## 한계 (VLM `4.8.0` 이 맡는다)

- **카메라 쪽으로 세로로 누움** — 박스가 오히려 좁아져 종횡비 조건에 걸리지 않고, 이번 시점에서는 검출 자체가 안 됐다.
- **하늘을 보고 누움** — 검출 점수가 대부분 0.1~0.4 였다. 임계값을 낮추면 같은 자리를 다른 물체로 읽은 헛검출도 함께 들어오므로 낮추지 않았다.
- **확정 뒤 박스가 흔들리면 풀린다** — run3 23:41:19.9 에 종횡비 3.7 인 채로 중심이 20px 넘게 움직여 해제됐다. 공장 모드 L3 는 래치되므로 경보에는 영향이 없고, 블랙박스 기록이 한 번 더 남는다.
