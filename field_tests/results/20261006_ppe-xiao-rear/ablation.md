# PPE 전처리·후처리 ablation — 2026-10-06 밤 후면 원본 프레임

포트폴리오 개선 계획 2단계. 같은 날 낮 촬영본의 ablation([낮 ablation](../20261006_ppe-xiao/ablation.md))은
저장 프레임이 판정을 덧그린 이미지라 다시 추론해야 하는 변형을 낼 수 없었다. 이 문서는 같은 날 밤 후면
재측정에서 남긴 **원본 프레임 5,841장**에 같은 도구(`tools/ppe/ablation.py`)를 돌려 그 변형들을 다시 낸 결과다.
집계 수치만 남긴다. 프레임에는 얼굴이 찍혀 있어 저장소에 넣지 않았고 외부로 보내지 않았다. 처리 시간 수치는
적지 않는다(같은 GPU 를 다른 작업이 쓸 수 있었다).

이 세션에는 위반 구간 두 개(`standing-nohelmet`, `standing-none`)만 있다. 그래서 **정상 착용자 오경보율은 잴
수 없고**, 아래 수치는 모두 «위반을 얼마나 위반으로 읽는가» 쪽이다. 사용자 결정(2026-10-06)에 따라 머리
클리핑 판정은 촬영 자세 때문에 생긴 것으로 보고, 비교는 **클리핑 제외 실효 성공률**을 기준으로 읽는다.

## 결론 먼저

1. **사람 크롭이 가장 큰 단계다.** Raw 검출기(풀프레임 PPE, 클리핑 규칙 끔, 누적 끔)의 판정 가능률은
   52.4%(1,502/2,866)이고, 사람 크롭을 더하면 96.0%(2,746/2,859)가 된다. 실효 성공률도 52.4% → 96.0% 다.
2. **머리 클리핑 필터는 이 데이터에서 비용만 보인다.** 필터를 더하면 249판정이 확인불가로 바뀌어 판정
   가능률이 96.0% → 87.3% 로 내려간다. 필터가 없을 때 그 249판정은 모두 위반으로 맞았다(실효 성공률 차이
   2,744 − 2,495 = 249). 클리핑을 뺀 판정끼리 보면 95.6% 다. 필터가 막으려는 사고, 곧 머리가 잘려 안전모가
   보이지 않는 착용자를 미착용으로 읽는 오경보는 착용 구간이 없어 이 세션으로 잴 수 없다.
3. **시간 누적은 프레임 판정을 바꾸지 않고 첫 경보를 0.1~0.2초 늦춘다.** 위반 에피소드 3개의 첫 경보 시각이
   누적 없이 0.6 · 0.8 · 0.8초, 누적(1.5초 안 3회)을 넣으면 0.7 · 0.9 · 1.0초다. 누적의 이득은 낮 기록 판정에서
   잰 «끄면 정상 오경보율 0% → 25%(1/4)» 다([낮 ablation](../20261006_ppe-xiao/ablation.md)).
4. **크롭 여유는 0.08 이 가장 낫다.** 클리핑 제외 실효 성공률이 0.08 에서 95.6%, 0.15 에서 95.1%, 0.25 에서
   94.3% 다. 여유 0 은 1.0% 로 무너지는데, 모델 때문이 아니다. 머리 박스 상단이 크롭 상단에 닿아 클리핑 규칙이
   구간 안 2,859판정 중 2,686판정을 확인불가로 돌린다. 여유 0 과 클리핑 규칙은 함께 쓸 수 없는 조합이다.
5. **conf 임계값은 낮출수록 위반을 조금 더 맞힌다.** 클리핑 제외 실효 성공률이 0.3 에서 96.3%, 0.5(배포값)에서
   95.6%, 0.7 에서 94.1% 다. 대가는 착용자 오경보 쪽에 있을 것으로 보지만, 이 세션으로는 잴 수 없다.
6. 절반 해상도 크롭, 가장 큰 사람만 판정, 프레임 좌표 클리핑(런타임 방식), 누적 해제 규칙(clear-1·3·5)은
   클리핑 제외 실효 성공률이 base 와 0.2%p 안이다.

## 최종 조합을 고른 이유

계획서 2단계의 완료 기준(각 단계의 이득과 손실을 수치로 설명하고 최종 조합을 고른 이유를 남긴다)에 맞춰
배포 설정(크롭 여유 0.08, conf 0.5, 크롭 좌표 머리 클리핑, 1.5초 안 3회 누적)을 단계별로 다시 본다.

| 단계 | 근거 | 판단 |
|---|---|---|
| 사람 크롭 · 여유 0.08 | 이 세션: 판정 가능률 52.4% → 96.0%, 여유 0.08 이 0.15·0.25 보다 높음 | 측정으로 뒷받침된다 |
| conf 0.5 | 이 세션: 0.3~0.7 사이 위반 쪽 차이 2.2%p, 착용자 쪽 비용은 미측정 | 바꿀 근거가 없어 유지한다 |
| 머리 클리핑 필터 | 이 세션: 비용 249판정(8.7%p)만 측정됨 | 유지 근거는 설계 의도뿐이고 **아직 측정되지 않았다** |
| 시간 누적 1.5초 / 3회 | 낮 기록: 끄면 정상 오경보 1/4 · 이 세션: 지연 0.1~0.2초 | 이득이 비용보다 커서 유지한다 |

머리 클리핑 필터와 conf 임계값은 착용 구간이 있는 원본 촬영으로 다시 판단해야 한다(아래 «다음 촬영»).

## 입력과 조건

- 세션: `field_tests/results/20261006_ppe-xiao-rear/session.json` (mechdog-01, 시나리오 `xiao-rear`, 계획 `plan.json`)
- 길이 360.1초, 프레임 5,841장(약 16.2fps). 라벨 구간 안 프레임은 `standing-nohelmet` 1,285장,
  `standing-none` 1,581장이고 방향은 후면 하나다. `standing-none` 은 중간에 끊겨 388장·1,193장의 두 에피소드로
  나뉘므로 위반 에피소드는 3개다.
- 모델: `models/ppe.onnx` sha256 `145c2dc9…790e2`(세션 기록과 같음, ppe-v5), `models/coco.onnx` sha256 `c5c2d13e…`
- 캐시: 크롭 여유 0 · 0.08 · 0.15 · 0.25, 축소 배율 0.5, PPE conf 하한 0.1, 풀프레임 검출 1회, 사람 검출 conf 0.5
- 재현 확인: base 재추론과 기록 판정의 프레임별 판정 일치율은 세션 전체 5,841장에서 92.8% 다. 구간 안
  2,866장에서는 98.5% 였다([v4 대 v5 비교](v4-vs-v5.md)).
- 평가 단위: 사람 크롭 변형은 사람마다 판정하고(구간 안 2,859판정), 풀프레임 변형은 프레임마다 하나를
  판정한다(2,866판정). 구간 안 프레임에는 사람이 한 명이거나 없으므로 두 단위는 거의 같다. 차이 7은 다시
  돌린 사람 검출이 아무도 찾지 못한 프레임이다.

## 단계 누적 표 (계획서 2단계 표)

앞 단계에 한 단계씩 더한다. 마지막 단계는 배포 설정(base)과 같다.

| 단계 | 판정 가능률 | 확인불가율 | 실효 성공률 | 클리핑 제외 실효 성공률 | 적합으로 오판 | 첫 경보 시각(에피소드 3개) |
|---|---|---|---|---|---|---|

읽을 것

- **gate-off 와 half-res 의 P95 가 10초를 넘는 것은 한 에피소드 때문이다.** 두 변형 모두 `standing-none` 앞
  에피소드(388장)의 첫 경보가 늦었고(12.4초 · 11.7초), 나머지 두 에피소드는 1.3초 안이다. 에피소드 3개로 낸
  P95 라 판정 시간 비교에는 쓰지 않는다.
- **gate-off 는 클리핑 규칙을 켠 채 풀프레임을 본다.** 그래서 단계 누적 표의 Raw(클리핑 끔)보다 판정 가능률이
  낮다(46.2% 대 52.4%).
- **pad-0 의 recall 1/3 은 클리핑 규칙 탓이다.** 거의 모든 판정이 머리 클리핑 확인불가라 `standing-none` 의 두
  에피소드에서 경보가 나지 않았다.
- 보고서 원본 표의 확인불가 사유 열(머리 미검출 등)은 구간 밖 프레임까지 센 세션 전체 값이라 이 문서에 옮기지
  않았다.

## 잴 수 없는 것

- **정상 착용자 오경보율.** 착용 구간이 없다. 머리 클리핑 필터와 conf 임계값의 비용이 이 칸에 있다.
- **후면 밖의 방향.** 후면 한 방향만 찍었다. 낮 세션에서 판정 가능률이 가장 낮던 좌측이 빠져 있다.
- **일반화.** 한 사람·한 장소·한 세션이다. 연속 프레임이라 판정끼리 독립이 아니어서 차이에 통계 검정을
  붙이지 않았다.

## 다음 촬영

정상 오경보율 열을 채우려면 낮 세션과 같은 직립 4구간(`standing-all` · `nohelmet` · `novest` · `none`) × 4방향을
**원본 프레임을 저장하며** 다시 찍어야 한다. 촬영은 `ppe_live_check` 에 `--save-raw-dir` 를 붙여 돌리고,
이어서 아래 재현 명령의 `--frames` 를 그 폴더로 바꾸면 이 문서의 표가 C1~C3 와 오경보율까지 채워진다.

## 재현 명령

```bash
# 1) 추론 캐시 (모델·원본 프레임 필요. 캐시는 저장소 밖에 둔다 — 박스 좌표만 담긴다)
python tools/ppe/ablation.py infer \
  --frames field_tests/results/20261006_ppe-xiao-rear/raw \
  --models-dir models --cache <저장소 밖>/cache_rear.json --scales 0.5
# 2) 변형별 표와 단계 누적 표 (모델 불필요). 이 계획에는 합격 기준이 없어 C1~C3 는 `-` 로 나온다
python tools/ppe/ablation.py report field_tests/results/20261006_ppe-xiao-rear/session.json \
  --plan field_tests/results/20261006_ppe-xiao-rear/plan.json \
  --cache <저장소 밖>/cache_rear.json --out <저장소 밖>/ablation_rear.md
```

에피소드별 첫 경보 시각은 `episode_eval.evaluate` 의 `episodes[*].first_alarm_s` 를 변형마다 읽어 적었다.
