# 선회율 곡선 실측과 그 재는 법 — 2026-09-18

**조향 명령(각도)이 실제 회전(°/s)으로 얼마나 바뀌는지를 처음 곡선으로 냈다.** 지금까지는
`±20°` 한 점씩만 있었고, 그 한 점에서 세운 *"데드밴드 3.3°"* 모델로 보정값을 정했다.
**곡선을 보니 그 모델이 틀렸다**(4절).

| 항목 | 값 |
| --- | --- |
| 기체 | **`mechdog-01`** · 카메라 탑재 상태 · 배터리 8.2 → 7.6V |
| 바닥 | 실내 장판 (2026-09-11 측정과 같은 바닥) |
| 도구 | 런타임 + `POST /api/command/drive` (`MANUAL`) · `yaw_rate_deg_s` (WBS 4.1.4) |
| 원자료 | `TEST_MECHDOG/results/20260918_turn-curve/` |

> ⚠️ **아래 숫자는 전부 `mechdog-01` 한 대의 것이다.** 비대칭의 출처가 개체별 서보
> 오프셋이라 **기체마다 방향도 크기도 다르다** — `mechdog-02` 는 직진 편향이 아예
> **반대쪽**이다(`WBS 2.2.3` ⑦). **복사 금지**([CONTRIBUTING 6절](../../CONTRIBUTING.md)).

## 1. 재는 법 — 다른 기체도 이대로 한다

`tools/gait_calibrate.py` 는 *"IMU yaw 잡음(±10~30°/s)이 재려는 선회율보다 크다"* 고 적어
두고 **사람이 줄자·각도기로** 재게 했다. **1초 평균에는 해당하지 않는다** — 이번에 정지
표준오차가 **0.14 °/s**, 걷는 중에도 **0.13~0.33 °/s** 였다. 4~9 °/s 신호를 충분히 분리한다.
그래서 **줄자 없이 곡선을 그릴 수 있다.**

### 절차

```powershell
# 0) 로그를 갈아 끼운다 (새 런이 이어 붙는다)
Rename-Item logs\mechdog-01.jsonl mechdog-01_<날짜>_before.jsonl

# 1) 런타임을 띄운다 — yaw_rate_deg_s 를 1초 요약에 남기는 주체다
python -m host.runtime --device <unit-id> --dashboard-port 8000
```

2. 관제 화면 「실제 장비 명령」에서 **사람이** `안전 해제(RESET_SAFE)` 를 누른다.
   순찰 시작은 누르지 않는다 — 수동 구동이다.
3. `POST /api/command/manual {"on": true}` → 각 점마다
   `POST /api/command/drive {"step": 60, "angle": <각도>}` 를 넣고 **8초 뒤 `{0,0}`**.
4. **점 사이마다 기체를 원위치시킨다.** 8초면 약 83cm 전진하고, 6점이면 5m 를 간다.
5. 각도 목록은 **양방향 최소 3점 + 0°** — 예 `0 · ±12 · ±20 · ±28`. `0°` 는 직진
   드리프트를 직접 주는 점이라 **빼면 안 된다**(4절이 그것으로 모델을 뒤집었다).

### 값을 내는 법

순 회전 = **구동창 평균 − 그 부팅의 정지 기준선**

| 규칙 | 이유 |
| :--- | :--- |
| 기준선은 **구동창 앞뒤 정지창**에서 딴다 | 바이어스가 천천히 흐르는 것을 상쇄한다 |
| **같은 부팅 안에서만** 뺀다 | ⚠️ 자이로 바이어스가 **부팅마다 다르다.** 이번 세 부팅에서 `+38.4` / `+0.2` / `−1.1` °/s 였다. 한 번은 38 °/s 였는데 그것을 모르고 생값을 읽으면 4 °/s 신호가 통째로 묻힌다 |
| 구동 첫 초·정지 첫 초는 버린다 | 가속·감쇠가 섞인다 |
| 기준선 표본은 **\|v\| ≤ 5 °/s** 만 | 운용자가 기체를 손으로 옮기면 **35~40 °/s** 가 찍힌다. (그 자체가 센서가 실제 회전을 분해한다는 증거다) |

### 함께 확인할 것

- **배터리를 만충으로 시작한다.** 전압이 낮으면 값이 흐르고, 무엇보다 다음 항목이 걸린다.
- ⚠️ **텔레메트리가 조용히 멈출 수 있다.** 이번 측정 중 여러 번 `accepted` 가 0~2/s 로
  떨어졌고 그때 ACK 는 10/s, PING 20/20, RTT 3.5ms 로 **링크는 멀쩡했다.** 원인 미확정이며
  [#202](https://github.com/PJW-1/mechadog/pull/202) 가 사유를 UART 에 남기게 했다.
  **`accepted` 가 10/s 인지 확인하고 시작하고, 떨어지면 그 구간 값은 버린다.**
- 진단은 `acks` 와 `accepted` 를 **나눠 본다** — `acks` 10/s 인데 `accepted` 0 이면 로봇은
  살아 있고 발행만 막힌 것이다. 통째로 0 이면 전원이 꺼진 것이다.

90도다. **2026-09-11 에 줄자로 잰 `1.0` 의 1.9배**다 — 방법도 날도 다르므로 둘 다 남긴다

`+20` 이 부팅 B 에서 **5.57**, 부팅 C 에서 **6.99** 였다. 같은 기체·같은 바닥·같은 각도다.

⚠️ **이것이 개루프 보정의 정확도 바닥이다.** 곡선을 정교하게 역산해도 다음 부팅에서
그만큼 어긋난다. 제대로 된 해법은 **요를 보고 닫는 것**이고, 이번 측정이 그 재료(요 계측이
쓸 만하다는 것)를 확인했다.

## 3. 조향 능력만 떼어내면 **우측이 더 강하다**

순 회전에는 드리프트가 섞여 있다. 빼면 이렇다.

| \|각도\| | 좌 순회전 | 우 순회전 | 좌 조향분 | 우 조향분 | **우/좌 조향** |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 12 | +5.67 | −2.27 | 3.80 | 4.14 | **1.09** |
| 20 | +6.99 | −4.04 | 5.12 | 5.91 | **1.15** |
| 28 | +9.41 | −7.90 | 7.54 | 9.77 | **1.30** |

**기체의 조향 능력은 우측이 9~30% 강하다.** 겉보기 좌우 차이(같은 각도에서 좌/우
1.19~2.50배)는 **거의 전부 드리프트가 만든다** — 좌회전은 1.87 을 공짜로 얻고 우회전은
그만큼 먼저 갚는다.

> **즉 *"우회전이 약하다"* 가 아니라 *"로봇이 항상 왼쪽으로 휜다"* 다.** 같은 현상의 다른
> 이름이 아니고 고칠 대상이 다르다.

⚠️ 위 분해는 *"드리프트가 조향과 무관하게 일정하다"* 는 가정이다. 구간 기울기가 0.17~0.48
로 흔들리니 완전한 모델은 아니다 — 순서와 크기가 일관되게 나온다는 것까지가 확인된 전부다.

## 4. 정정 — **데드밴드는 없었다**

2026-09-12 에 두 점(`-3` 효과 없음 · `-9` 거의 일자)으로 *"우선회에 약 3.3° 데드밴드가
있다"* 고 세웠고, 그 모델이 `2.2.3`·`3.5.4`·`tracker.py`·시험 상수에 근거로 적혀 있었다.

**곡선은 0 을 연속으로 통과한다.**

```
angle   0  →  +1.87   (좌)
angle -12  →  -2.27   (우)
        그 사이 어딘가에서 0 을 지난다 — 평평한 구간이 없다
```

영점(회전이 0 이 되는 각도)을 보간하면 **−5.4°** 다. 그리고 드리프트를 우선회로 상쇄하는 데
필요한 각도도 `1.87 / 0.346 = 5.4°` 로 **같은 숫자를 준다.**

| 예전 설명 | 실제 |
| :--- | :--- |
| 3.3° 안의 명령은 **아무 일도 하지 않는다** | 한다. 다만 **드리프트가 더 커서 순 회전이 여전히 좌**다 |
| `-3` 이 효과 없던 이유는 데드밴드 | 영점이 `-5.4` 라 `-3` 은 **아직 좌회전 구간**이다 |
| 보정 `-8.0` 이 드리프트를 0 으로 만든다 | 영점은 `-5.4` 다. `-8.0` 은 **2.6° 과보정**이고 우측에 +0.9 °/s 덤을 준다 |

⚠️ **보정값 `-8.0` 은 바꾸지 않았다.** 방향별로 우선회에만 붙으므로 과보정이 곧 우측
가속이고, 그것이 최대 편차에서 좌우를 맞추는 방향이다(`-28` → 7.90 대 `+20` → 6.99).
바꾸려면 곡선 전체를 다시 맞춰야 하고, 그것은 부팅 간 25% 에 상당 부분 먹힌다.

### 좌측 보정을 다시 본 결과 — **상수로는 안 된다**

데드밴드가 없으니 *"좌측에도 같은 보정을 걸면 대칭이 되지 않나"* 를 곡선으로 확인했다.

영점이 `-5.4°` 이므로 **좌측 명령이 5.4° 보다 작으면 보정을 더한 뒤 순 회전이 우로
뒤집힌다.** 락온의 매핑에서 그 경계는 편차 **116px** 이다.

```
dev -112.6px → raw +5.19° + (-8.0) = -2.81°  →  순 회전 +0.90 (좌, 5.19 일 때의 17%)
dev  -68px   → raw +2.00° + (-8.0) = -6.00°  →  순 회전 -0.20 (우!  대상에서 멀어진다)
```

2026-09-18 오전에 좌측이 죽은 것이 이것이었다. **당시 설명("데드밴드에 먹혀 0")은 기전이
틀렸고 결과는 맞았다** — 실제로는 0 이 아니라 83% 손실이었고, 더 작은 편차에서는 부호까지
뒤집힌다.

좌우를 맞추려면 상수가 아니라 **재형성**이 필요하다. 우측 순회전에 맞추는 좌측 각도는
`m=1 → +23° · m=0.5 → +5.6° · m=0.25 → +2.0° · m=0.1 → −0.8°` 로, 중간은 줄이고 최대는
늘려야 한다. **지금 하지 않는다** — 남은 비대칭은 수렴 속도 차이고 발산이 아니며, 부팅 간
25% 에 상당 부분 먹힌다. 제대로 하려면 요 폐루프다.
