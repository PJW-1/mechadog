## 1. 착수 확인 H1~H3 — 셋만 통과하면 된다

> 통합 검수 게이트 `G1~G3`와는 다른 것이다. 이쪽은 **하드웨어를 만지기 전에** 보는 셋이다.

| # | 확인 | 통과 못 하면 |
| :-: | :--- | :--- |
| **H1** | **순정 펌웨어를 백업하고 복원까지 성공** (OI-20) | ⚠️ **커스텀 펌웨어 업로드 금지.** 되돌릴 수단이 없다 |
| **H2** | 메인 ESP32 가 Wi-Fi STA 로 공유기에 접속 (OI-1 / RISK-01) | 명령 경로를 **XIAO UART 중계**로 바꾼다 (+2.0 M/D, 가정 A-1) |
| **H3** | Phase 2 최종 구성을 **마스트 높이에** 얹고 Trot 3m · 최대 조향각 선회 1바퀴 · 10분 연속 (OI-2 / RISK-02) | Phase 2 를 **ArUco 마커 구역 정의**로 대체 |

**H1 → H2 순서를 지킨다.** 백업 전에 업로드하면 순정으로 돌아갈 수 없다.

> 나쁠 가능성을 전제로 하는 작업**이다. 그 덤프를 현재 상태 위에 덮어쓰면 실패 시 순정도

> 소스와 라이브러리뿐이다. 따라서 **이 덤프가 유일한 순정 복원 수단**이며, 이제 그것이
> 실제로 작동함이 증명됐다.
>
> 순정은 **MicroPython 기반**이라 우리 Arduino C++ 스택과 코드를 한 줄도 공유하지 않는다.
> 우리 쪽이 어떻게 망가져도 순정 폴백은 영향받지 않는다.

> 개체 보정값은 별도로 `config/devices/mechdog-01.yaml` 에 넣어 두었으므로,
> 덤프가 못 쓰는 파일이더라도 보정값은 잃지 않는다.

> ⚠️ **H2 는 공유기가 아니라 XIAO 카메라 모듈의 AP(`HW_ESP32S3CAM`)에 붙어 통과했다.**
> *"메인 ESP32 의 Wi-Fi 가 살아 있는가"*(RISK-01)는 이것으로 닫힌다. 그러나
> **RSSI −14 dBm 은 거의 맞닿은 거리**이므로 시연 거리의 도달성과는 무관하며,
> 실제 운용 토폴로지(공유기 중심)와 2.4GHz 커버리지는 `2.4.2` 에서 따로 본다
> (RISK-05).

> ⚠️ **두 측정치가 15배 차이 난다.** 1차 3.6ms 와 재측정 55.8ms 사이에 무언가 바뀌었는데
> **양쪽 다 측정 조건이 기록되지 않아 무엇이 바뀐지 알 수 없다.** 후보는 접속 대상(모듈 AP
> vs 공유기) · 거리 · 영상 동시 송출 · 로봇 대수다.
>
> 재측정치 최대 193.1ms 는 **명령 타임아웃 300ms 의 64%** 로 여유가 107ms 뿐이다. 지터가
> 뭉치면 페일세이프가 걸리므로 `2.4.2` 에서 다시 잴 때는 **접속 대상 · 거리 · 영상 송출
> 여부 · 로봇 대수와 p95·p99 를 함께 남긴다.** 평균과 최대만으로는 한 번 튀었는지 스무 번
> 튀었는지 구분할 수 없다.

> **H2 를 펌웨어 작업의 첫 항목으로 둔다.** 30분이면 되고, 실패하면 구조가 통째로 바뀐다.
> 실패 시 대비로 **여유 UART 핀이 노출되어 있는지**(OI-3)도 같이 본다.
>
> **H3 은 무게가 아니라 무게중심이 문제다.** LiDAR 는 마스트 위에 올라간다 — 바닥에 얹어
> 시험하면 통과해도 실제로는 넘어진다.

### ⚠️ 상시 점검 — 벤더 문서의 부품 번호를 신뢰하지 않는다

**세 번 어긋났다. 우연이 아니라 패턴으로 본다.**

| 부품 | 벤더 문서·통념 | 실물 | 어떻게 알았나 |
| :--- | :--- | :--- | :--- |
| IMU | MPU6050 (`0x68`) | **QMI8658 (`0x6A`)** | I2C 스캔 + `WHO_AM_I` 직접 읽기 |
| 초음파 I2C 핀 | 흔히 쓰는 SDA22/SCL21 | **SDA22 / SCL23** | 잘못된 핀으로 스캔해 순정 펌웨어의 센서 스레드를 방해한 뒤 벤더 헤더 확인 |
| 카메라 | OV2640 | **OV3660** | 펌웨어에서 `id.PID` 를 읽어 식별 |

**새 부품을 붙일 때는 데이터시트를 믿기 전에 실물에서 식별자를 읽는다** — I2C 주소·`WHO_AM_I`·`PID`
처럼 칩이 직접 답하는 값이다. 벤더 예제가 특정 부품 번호를 하드코딩하고 있으면 그 예제는 우리
개체에서 조용히 실패한다(IMU 가 정확히 그랬다).

가능하면 **두 부품을 모두 식별하는 코드**를 쓴다. 비전 펌웨어가 OV2640·OV3660 을 함께 처리하는
것이 그 형태다.

MechDog는 ESP32·8개 서보·초음파·IMU를 포함하며, WonderEcho/MP3는 Advanced/Ultimate 키트 구성품이다.
키트 등급이 확인되기 전에는 음성 모듈 보유를 확정하지 않는다.

8MB PSRAM과 HTTP 영상 스트리밍 예제는 제공되지만 VGA 15fps·E2E 250ms는 우리 구성에서 측정할 목표다.

## 2. LiDAR 노드 배선 `[P2]`

> ⚠️ **LiDAR 모델은 재선정 중이다.** 아래 내용은 LD19/D500을 선택할 경우의 잠정 배선안이다.
> 국내배송·비회원구매·무납땜 조건을 만족하는 모델과 실물 하네스를 확정하기 전에는 케이블을
> 발주하거나 결선하지 않는다. 다른 모델을 고르면 커넥터·전압·UART 속도·핀 배열을 새로 검증한다.

**보조배터리 → ESP32-DevKitC → LD19.** LiDAR 전원을 DevKit 의 `5V` 핀에서 뽑으므로
**GND 가 자동으로 공통**이 된다(UART 성립 조건). 하네스 4선을 핀에 하나씩 꽂으면 끝이고,
**납땜과 브레드보드는 쓰지 않는다.**

| LD19 핀 | ESP32 핀 | 비고 |
| :--- | :--- | :--- |
| Pin4 `P5V` | `5V` | 왼쪽 맨 아래 (`5VD`) |
| Pin3 `GND` | `GND` | GND 3개 중 아무거나 |
| Pin1 `Tx` | **`GPIO16`** (UART2 RX) | 오른쪽 |
| Pin2 `PWM` | 미연결 | 데이터시트: 미연결·Hi-Z 시 내부 제어 10Hz |

**실제로 연결하는 것은 3선이다.**

### 쓰면 안 되는 핀

| 핀 | 이유 |
| :--- | :--- |
| **GPIO6~11** | **플래시 메모리 연결. 사용 금지** |
| GPIO1 / GPIO3 | USB 시리얼 — 물리면 **펌웨어 업로드가 막히고 로그가 깨진다** |
| GPIO0 / GPIO2 / GPIO12 / GPIO15 | 스트래핑 핀 — 부팅 모드에 영향 |

GPIO16 대신 GPIO25 · 26 · 27 · 32 · 33 도 쓸 수 있다.

> ⚠️ **WROVER 는 GPIO16·17 을 PSRAM 이 점유한다.** 상품명에 `WROOM` 을 확인하고,
> WROVER 라면 RX 를 GPIO25 등으로 옮긴다.

### 연결 전에 반드시

| | |
| :--- | :--- |
| **기판 실크를 직접 대조한다** | 하네스 **선 색으로 핀을 판단하지 않는다.** 색은 제조사가 임의로 정한다. LD19 기판의 `TX/PWM/GND/P5V` 표기를 본다 |
| **멀티미터로 전원선을 확인한다** | 물리 핀 순서가 1차 출처로 확정되지 않았다. **역결선하면 LiDAR 가 파손된다** |
| **연결 후 `5V` 핀 전압을 잰다** | **4.5V 이상**이면 통합 유지, **미만이면 LiDAR 를 배터리에서 직접 급전**으로 분리한다 (LD19 허용 하한 4.5V) |

> **전압 강하는 딱 끊어지지 않고 서서히 나타난다.** DevKit USB 커넥터 하나에 DevKit(200mA) +
> LD19(200mA) ≈ 400mA 가 몰리는데, 500mA 폴리퓨즈 제품이면 마진이 얇다. 증상은
> *"가끔 리셋되고 이유 없이 불안정하다"* — **가장 찾기 어려운 형태의 고장이다.** 조립 직후에 잰다.

> **2대를 동시에 돌려본다.** LiDAR 는 3대 중 2대에 장착한다. 상호 간섭 여부가 OI-21(협동
> 시나리오)의 입력이다. 자기 차폐(스캔면이 몸통 최고점보다 낮으면 전방이 막힌다)도 함께 본다.

## 3. 발주

### 잠정 발주안 — LiDAR 확정 후 갱신

| 항목 | 수량 | 확인할 것 |
| :--- | ---: | :--- |

### 사지 않는 것

**A4 프린터 출력으로 끝나는 것** — ArUco 마커(구역 2~3장 + 사원증 1장). 사원증만 코팅하면 충분하다.
**USB 케이블** — 보유 케이블이 실물 단자와 맞으면 추가 구매하지 않는다. XIAO는 USB-C,
DevKit은 구매한 보드의 Micro-USB/USB-C 단자를 확인한다. 펌웨어 업로드에는 데이터 지원 케이블이 필요하다.

**부품 제외 근거**(MT3608 · TP4056 · LiPo · 벌크 커패시터 · MPU6050)는
[아키텍처 1.3](ARCHITECTURE.md)에 있다.

> **검토** — 로봇 본체 2S 여분 배터리. **시연 당일 방전이 유일하게 남는 전원 리스크다.**

> ⚠️ **H3 에서 무게 초과가 나와 LiPo 구성으로 되돌릴 경우**, 납땜 12~15점이 발생하고
> **순서를 지키지 않으면 LiDAR 가 파손된다** — ① MT3608 에 배터리만 물린다(LiDAR 미연결)
> → ② 멀티미터로 출력을 5V 로 맞춘다 → ③ 전원을 끊는다 → ④ 그 다음 LiDAR 를 연결한다.
> MT3608 은 가변저항 모듈이라 출하 상태가 5V 라는 보장이 없다. ②를 건너뛰는 것이 가장 흔한 사고다.
